## CAP-18 Testing

### Unit and widget tests: fakes

**Ditto does not load under a host `flutter test`.** Executed (ditto_live 5.2.0, Flutter
3.50.0, macOS host, a plain `test()` calling `Ditto.init()` and `Ditto.open`):

```text
DittoException(Failed to get application documents directory)
```

`Ditto.init()` asks `path_provider` for the documents directory, and a host test has no
platform plugins. With `XDG_DOCUMENTS_DIR` set it fails one step later, because the
native library is not in the test process:

```text
Invalid argument(s): Failed to lookup symbol 'ditto_logger_set_custom_log_cb': dlsym(RTLD_DEFAULT, ditto_logger_set_custom_log_cb): symbol not found
```

Nor can you mock the SDK: `Ditto`, `Store` and `Sync` are `final class`es
(`lib/src/ditto.dart`, `store/store.dart`, `sync.dart` @ `sdk-release-5.2.0`), so they
cannot be implemented or extended outside the package. So put Ditto behind your own
interface and test everything above it with a fake: the repository from
[widget-integration.md](widget-integration.md) implements the interface, and widget and
view-model tests get the fake.

```dart
import 'package:flutter/foundation.dart';
import 'package:flutter/widgets.dart';
import 'package:flutter_test/flutter_test.dart';

/// What the cars screen needs. The app's repository implements it with
/// Ditto; widget and unit tests use [FakeCars].
abstract interface class CarsSource {
  ValueListenable<List<Map<String, dynamic>>> get cars;
}

class FakeCars implements CarsSource {
  @override
  final ValueNotifier<List<Map<String, dynamic>>> cars = ValueNotifier(
    const [],
  );
}

class CarCount extends StatelessWidget {
  const CarCount({super.key, required this.source});

  final CarsSource source;

  @override
  Widget build(BuildContext context) => ValueListenableBuilder(
    valueListenable: source.cars,
    builder: (context, cars, _) => Text('${cars.length} cars'),
  );
}

void main() {
  testWidgets('shows the number of cars', (tester) async {
    final source = FakeCars();
    await tester.pumpWidget(
      Directionality(
        textDirection: TextDirection.ltr,
        child: CarCount(source: source),
      ),
    );
    expect(find.text('0 cars'), findsOneWidget);

    source.cars.value = [
      {'_id': 'car-1'},
    ];
    await tester.pump();
    expect(find.text('1 cars'), findsOneWidget);
  });
}
```
<!-- /snippet -->

Executed: this file passes under `flutter test` on the macOS host (Flutter 3.50.0),
with `ditto_live` 5.2.0 in the same package. Keep `package:ditto_live` imports out of
code that host tests load.

### Ditto in the loop: integration_test

Test the repository itself, and anything else that needs a real store, with
`integration_test` on a device, a simulator or emulator, or the desktop:
`flutter test integration_test/<file>.dart -d macos` (or `-d <device-id>`). Executed this
way: macOS, Linux (under `xvfb-run`), Windows, an Android API 34 emulator and an iOS
26.5 simulator (5.2.0; macOS also 5.0.4 and 5.1.0).

One instance per test, in its own temporary directory. Imports: `dart:io`,
`package:ditto_live/ditto_live.dart`.

<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```dart
/// Opens a Ditto instance for one integration test: a fresh temporary
/// directory, the offline license from `--dart-define-from-file`, every
/// peer-to-peer transport off. Closes it and deletes the directory after
/// [body], also when [body] fails.
Future<void> withTestDitto(Future<void> Function(Ditto ditto) body) async {
  await Ditto.init();
  // Tests only, not an app fix: re-opening Ditto in one process with logging
  // on can abort or hang it when the GC frees a handle of the closed one.
  DittoLogger.isEnabled = false;
  final directory = await Directory.systemTemp.createTemp('ditto_test_');
  try {
    final ditto = await Ditto.open(
      DittoConfig(persistenceDirectory: directory.path),
    );
    try {
      ditto.setOfflineOnlyLicenseToken(
        const String.fromEnvironment('DITTO_LICENSE'),
      );
      ditto.updateTransportConfig((config) {
        config.peerToPeer.bluetoothLE.isEnabled = false;
        config.peerToPeer.lan.isEnabled = false;
        config.peerToPeer.awdl.isEnabled = false;
        config.peerToPeer.wifiAware.isEnabled = false;
      });
      await body(ditto); // cancel observers and subscriptions in here
    } finally {
      await ditto.close();
    }
  } finally {
    try {
      await directory.delete(recursive: true);
    } on FileSystemException {
      // Windows keeps the directory locked for a while after close().
      if (!Platform.isWindows) rethrow;
    }
  }
}
```
<!-- /snippet -->

Executed (macOS, debug, 5.0.4, 5.1.0, 5.2.0): two tests in one file each see an empty
store and their own write.

- **Set a timeout.** `integration_test` runs with no per-test timeout, so a hang stalls
  the run: `IntegrationTestWidgetsFlutterBinding.ensureInitialized().defaultTestTimeout = const Timeout(Duration(minutes: 2));`
  as the first line of `main`.
- **Logging off in tests.** Opening a new instance after closing another in the same
  process aborted (5.0.4) or hung (5.1.0, 5.2.0) the test app on macOS when a handle of
  the closed instance was freed by the GC with logging on
  ([connect.md](connect.md#shutdown-and-ownership)); the fixture's probes run with
  `DittoLogger.isEnabled = false` for that reason. This is a test-harness workaround.
  In an app, keep one instance instead.
- **Teardown order:** cancel observers and subscriptions inside the test body, then
  `await ditto.close()`, then delete the directory. On Windows the directory can stay
  locked after `close()`: deleting it failed for 5 s with `errno = 32` (CI, 5.2.0), so
  the helper leaves it there.
- **The license** is read with `String.fromEnvironment('DITTO_LICENSE')` and passed as
  `--dart-define-from-file=<file>`, a JSON file with mode 600 that you delete after the
  run. That keeps it out of the command you type, shell history and the command line a
  CI log echoes, which `--dart-define=DITTO_LICENSE=…` does not. It is not hidden from
  the build machine: the flutter tool hands every define to the Dart compiler as
  `-D<name>=<value>`, and to Gradle (`-Pdart-defines=`) and Xcode's build step
  (`--DartDefines=`) base64-encoded, so a process listing during the build shows it
  (`flutter_tools` 3.50.0: `compile.dart`, `build_info.dart`, `bin/xcode_backend.dart`).
  Build on a machine you trust, with a license you can replace. Never commit a license,
  and never upload a build directory: compiled builds embed every define.
- **Keep `DITTO_*` out of the environment** of `flutter test`: Ditto reads `DITTO_*`
  process variables as system parameters, and logged
  `The Ditto environment variable offline_license is set, but it is not a known system parameter, so it is being ignored`
  for an exported `DITTO_OFFLINE_LICENSE` (executed, macOS release build, 5.2.0).

### Waiting for results

The probes wait on real time, which `integration_test`'s binding allows inside
`testWidgets`: poll a condition every 50 ms with a deadline (`waitUntil`), and for
widgets pump frames in a loop, `await tester.pump(const Duration(milliseconds: 50))`,
until the finder matches. To assert that nothing arrives, check the condition
throughout a fixed window (5 s for "denied" in the two-peer probes). Do not sleep a
fixed time and then assert. `tester.pumpAndSettle()` and `tester.runAsync()` with live
observers were not used or tested here.

### Two peers in one test

Two instances in separate directories, one listening on TCP `127.0.0.1:<free port>` and
one connecting, sync with each other and with nothing else when every peer-to-peer
transport is off: [presence.md](presence.md#two-peers-in-one-process). Executed on macOS,
5.0.4 to 5.2.0.

### Web: flutter drive

Flutter runs `integration_test` in a browser through `flutter drive`
(<https://docs.flutter.dev/testing/integration-tests#test-in-a-web-browser>):
`flutter drive --driver=test_driver/integration_test.dart --target=integration_test/<file>.dart -d chrome --headless`,
with a ChromeDriver matching the local Chrome listening on port 4444, and one `--target`
per run. `test_driver/integration_test.dart` is `integrationDriver()` from
`package:integration_test/integration_test_driver.dart`. Executed (Chrome 157 with
ChromeDriver 157, debug, 5.0.4 to 5.2.0). What the fixture learned:

- The target's directory is its app root: a web target cannot import files above it,
  so web tests need their own helpers beside them.
- No `dart:io` calls and no temporary directory: pass no `persistenceDirectory`; the store is
  in memory ([web.md](web.md#in-memory-store-and-reload)).
- The compiled test embeds the defines, the license included; delete the build output.

### Platform quirks

- **iOS Simulator and Android: `flutter test` uninstalls the app after the run**,
  deleting its data. Pass `--no-uninstall` when a later run must see the store
  (executed, iOS Simulator migration test).
- **iOS Simulator, first run after boot:** in CI the first `flutter test` after booting
  a simulator once ended with `Error waiting for a debug connection: The log reader failed unexpectedly`.
  After the fixture started launching a stock app once after each boot, later CI runs
  passed on the first attempt.
- **Linux desktop in CI** needs a display: run under `xvfb-run`.
