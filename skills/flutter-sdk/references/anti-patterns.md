# Anti-patterns — Flutter

Each of these compiles, or fails in a way that sends people the wrong way. Most give no
error at runtime: the symptom is a leak, a wrong result, or a screen that stops
updating. The one-line rules are in
[`SKILL.md` § Anti-patterns](../SKILL.md#anti-patterns); this file carries the code and
the diagnosis. Executed results are macOS debug builds with Flutter 3.50.0 unless stated.

## StreamBuilder over changes

<!-- snippet: flutter-anti-patterns-1 -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```dart
// Anti-pattern: the widget tree subscribes directly to an observer's
// single-subscription `changes` stream.
class LeakyCarsRepository {
  LeakyCarsRepository(Ditto ditto)
    : observer = ditto.store.registerObserver('SELECT * FROM cars');

  final StoreObserver observer;

  Stream<QueryResult> get changes => observer.changes;
}

class LeakyCarsScreen extends StatelessWidget {
  const LeakyCarsScreen({super.key, required this.repository});

  final LeakyCarsRepository repository;

  @override
  Widget build(BuildContext context) => StreamBuilder<QueryResult>(
    // Disposing this StreamBuilder cancels its listener but not the observer;
    // building the screen again listens a second time and throws StateError.
    stream: repository.changes,
    builder: (context, snapshot) =>
        Text('${snapshot.data?.items.length ?? 0} cars'),
  );
}
```
<!-- /snippet -->

**Right:** a repository registers the observer once, holds the one `changes` listener and
exposes a `ValueNotifier`; screens use `ListenableBuilder`. The code is
`CarsRepository` in [observers.md](observers.md#the-default-no-onchange-one-listener).

**Symptom:** building the screen a second time throws a
`StateError` whose message is `Stream has already been listened to.`, and the observer the first
`StreamBuilder` listened to stays live (`isCancelled` `false`) after its widget is gone
(executed, 5.0.4, 5.1.0, 5.2.0).

## setState with result.items

Wrong: `setState(() => _cars = result.items);` with `List<QueryResultItem> _cars`.

Right (analyzed by the skill's Dart gate, not executed):

```dart
import 'package:ditto_live/ditto_live.dart';

/// Right: copy the documents out of the result.
Future<List<Map<String, dynamic>>> loadCars(Ditto ditto) async {
  final result = await ditto.store.execute('SELECT * FROM cars');
  return result.items.map((item) => item.value).toList();
}
```

**Symptom:** `flutter analyze` (and the compiler):
`A value of type 'Iterable<QueryResultItem>' can't be assigned to a variable of type 'List<QueryResultItem>'`
(`invalid_assignment`). `items` is an `Iterable` that reads from the native result each
time it is iterated (executed: it is not a `List`); declaring the field `Iterable`
silences the error, keeps the native result alive inside widget state, and decodes
every document again on each rebuild (source, `store/execute.dart` @
`sdk-release-5.2.0`; [lifetimes.md](lifetimes.md#what-to-retain-and-the-symptom-if-you-dont)).

## onChange on a long-lived observer

Wrong: `ditto.store.registerObserver(query, onChange: (result) => …)` for a screen or
repository that lives a long time (also `registerObserverV2` and
`registerObserverWithSignalNext` with `onChange`).

**Right:** no `onChange`; one `changes` listener, as in
[observers.md](observers.md#the-default-no-onchange-one-listener).

**Symptom:** memory grows with every change and is freed only on `cancel()`: the
observer also buffers each result in its unlistened `changes` stream. Executed (V1 on
5.0.4 to 5.2.0, V2 on 5.1.0 and 5.2.0): after 6 `onChange` calls, a late listener
received all 6 buffered results.

## close() in State.dispose()

Wrong: `@override void dispose() { widget.ditto.close(); super.dispose(); }`.

**Right:** close once, when the app exits (`AppLifecycleListener.onExitRequested` on
desktop), after cancelling observers; iOS and Android end the process without it
([widget-integration.md](widget-integration.md#app-lifecycle)).

**Symptom:** `flutter analyze`: `'Future'-returning calls in a non-'async' function`
(`discarded_futures`). At runtime every later Ditto call on any screen fails with
`DittoClosedException` (executed: calls after `close()`), and re-opening is the hazard
below.

## Re-opening Ditto in the same process

Wrong: closing Ditto to "reset" it, or after a failed `configure`, and calling
`Ditto.open` again.

**Right:** one instance for the app's lifetime; after a failed open or configure, close,
show the error and have the user relaunch ([connect.md](connect.md#shutdown-and-ownership)).

**Symptom:** with logging on, when the garbage collector freed a handle of the closed
instance: `EXC_CRASH (SIGABRT)` at `dart::Assert::Fail` (5.0.4, 3 of 3 runs), or a hang
(5.1.0 3 of 3, 5.2.0 2 of 3). `await close()` does not prevent it. Turning logging off
is not the fix.

## Surviving hot restart with a static holder

Wrong: a static or top-level holder that "reuses" the open instance across `R`, or
retrying `Ditto.open` until it succeeds.

**Right:** in debug builds only, a new persistence directory per launch; otherwise a full
restart ([widget-integration.md](widget-integration.md#hot-restart)).

**Symptom:** a hot restart resets every static, so the holder is empty and the old
instance still holds the directory: `DittoException(File already locked, …)` on 5.0.4
and 5.2.0 (macOS, and Chrome on 5.2.0), `Ditto.open` never completing on 5.1.0; a
retry every 500 ms for 20 s never succeeded.

## Gating P2P on defaultTargetPlatform

Wrong: `if (defaultTargetPlatform == TargetPlatform.macOS) { …lan.isEnabled = true; }`.

**Right:** `kIsWeb` first, then `Ditto.currentPlatform`: `enablePeerToPeer` in
[web.md](web.md#code-that-compiles-on-web).

**Symptom:** in a browser `defaultTargetPlatform` is the host OS, so the gate enables LAN
on web, and `DittoException(<validation> Expected valid TransportConfig. Invalid config: The following P2P transports are enabled in the transport config but are not supported in the current environment: LAN)`
is thrown by `sync.start()` on 5.2.0 and by `updateTransportConfig` on 5.0.4 and 5.1.0
(executed, Chrome).

## await updateTransportConfig

Wrong: `await ditto.updateTransportConfig((config) { … });`.

**Right:** call it without `await`: it returns `void` and applies the change when the
callback returns ([transports.md](transports.md#cap-06-customizing-transports)).

**Symptom:** `flutter analyze`: `This expression has a type of 'void' so its value can't be used`
(`use_of_void_result`, an error) and `Uses 'await' on an instance of 'void'`
(`await_only_futures`).

## setAllPeerToPeerEnabled(false) on 5.0.x

Wrong: `config.setAllPeerToPeerEnabled(false)` or `withAllPeerToPeerEnabled(false)` to
turn peer-to-peer off on 5.0.x.

**Right:** set each transport's `isEnabled = false`: `disablePeerToPeer` in
[transports.md](transports.md#cap-06-customizing-transports).

**Symptom:** none visible: on iOS and macOS AWDL, and on Android Wi-Fi Aware, stay on
(`transport_config.dart:170-183`, ditto_live 5.0.4; fixed in 5.1.0; not executed).

## Building web with --wasm

Wrong: `flutter build web --wasm`.

**Right:** the default `flutter build web` (dart2js) ([web.md](web.md#build-modes)).

**Symptom:** Ditto opens, then every query result after the first is the first one
again: a second `INSERT` reports the first one's IDs and `SELECT` returns 0 items
(executed, release, Chrome 157, 5.1.0 and 5.2.0).

## persistenceDirectory 'ditto' in production

Wrong: copying the install guide's hot-restart sample, which passes
`persistenceDirectory: 'ditto'` outside debug builds.

**Right:** pass no `persistenceDirectory` in release builds; the SDK default is
`ditto-{databaseID}` ([widget-integration.md](widget-integration.md#hot-restart)).

**Symptom:** none at once. `'ditto'` resolves to a different directory from the v5
default, so an app that shipped with the default opens an empty store and its users'
local data seems gone (inference from the path rules; not run).

## Random().nextInt(1 << 32) on web

Wrong: `'ditto-${Random().nextInt(1 << 32)}'` for a per-launch directory (the install
guide's form).

**Right:** `'ditto-debug-${DateTime.now().microsecondsSinceEpoch}'`, in debug builds
only ([widget-integration.md](widget-integration.md#hot-restart)).

**Symptom:** under dart2js `1 << 32` is `0`, and `Random().nextInt(0)` throws
`RangeError`, so the web build fails at startup; native builds work.

## Provider.value for a ChangeNotifier, context.read in build

Wrong: `Provider<CarsViewModel>.value(value: viewModel, …)`, and
`context.read<CarsViewModel>()` inside `build`.

**Right:** `ChangeNotifierProvider<CarsViewModel>.value`, and `context.watch` in `build`
([widget-integration.md](widget-integration.md#default-pattern-service-repository-view-model)).

**Symptom:** plain `Provider` throws a `FlutterError` in debug builds for a `Listenable`
("Tried to use Provider with a subtype of Listenable/Stream") and never rebuilds;
`context.read` in `build` shows the first value forever (provider 6.1.5+1 source and
docs).

## Claims to ignore

Statements found in circulation that are wrong for `ditto_live`:

| Claim | Fact |
|---|---|
| "Observers require `ORDER BY`" | A plain `SELECT … WHERE` observer delivers its match (executed, all three lines) |
| "Attachments need a `CREATE TABLE` first" | No schema step: insert the `Attachment` in the document with `(photo ATTACHMENT)` in the collection definition ([attachments.md](attachments.md#create-and-store)) |
| "Set `DQL_RESTRICT_SUBSCRIPTION` to allow `LIMIT`" | The parameter is `dql_restrict_subscriptions` (default `true`, `crates/dittoffi/src/store/dql/ffi_access.rs` @ `sdk-release-5.2.0`). Leave it on: limit and sort in the local query ([sync.md](sync.md#limit-and-order-by-are-rejected)) |
| "Bonjour type `_ditto._tcp`" | The install guide's `NSBonjourServices` entry is `_http-alt._tcp.`, trailing dot included (<https://docs.ditto.live/sdk/latest/install-guides/flutter>); the iOS keys are in [setup.md](setup.md#declarations) |
| "No `signalNext` in Flutter" | `registerObserverWithSignalNext` exists from 5.1.0 and works on web ([observers.md](observers.md#back-pressure-registerobserverwithsignalnext-510)) |
| "`ConnectionType` has four values" | Four on 5.0.x, five from 5.1.0 ([presence.md](presence.md#connection-types)) |
| "`DittoException` implements `DittoError`" | Unrelated types: catch both ([errors.md](errors.md#two-unrelated-families)) |
| "`SyncSubscription.query`" | It is `queryString` |
