## Default pattern: service, repository, view model

1. **`DittoService`** owns the one `Ditto`. `main` calls
   `WidgetsFlutterBinding.ensureInitialized()`, opens it, and only then `runApp`: see
   `DittoService` and `startCarsApp` in
   [connect.md](connect.md#open-configure-close-on-failure).
2. **A repository per query** registers its observer once, without `onChange`, holds the
   one `changes` listener, and exposes a `ValueNotifier`. Its `dispose()` cancels the
   listener, then the observer, while Ditto is open.
3. **A `ChangeNotifier` view model** derives what the screen shows.
4. **`ListenableBuilder`** rebuilds from the view model.

The repository (also in [observers.md](observers.md#cap-11-observers-and-live-queries)):

```dart
/// Owns the observer for as long as the data is needed, independent of any
/// one widget. Screens listen to [cars]; [dispose] stops observing.
class CarsRepository {
  CarsRepository(Ditto ditto) {
    // No onChange (it would also buffer every result in the unlistened
    // `changes` stream, 5.0.0 through 5.2.0). This class holds the one
    // `changes` listener, started right away.
    _observer = ditto.store.registerObserver('SELECT * FROM cars');
    _changes = _observer.changes.listen((result) {
      cars.value = result.items.map((item) => item.value).toList();
    });
  }

  final cars = ValueNotifier<List<Map<String, dynamic>>>(const []);
  late final StoreObserver _observer;
  late final StreamSubscription<QueryResult> _changes;

  bool get isObserving => !_observer.isCancelled;

  /// Call while Ditto is still open: the listener first, then the observer.
  Future<void> dispose() async {
    await _changes.cancel();
    _observer.cancel();
    cars.dispose();
  }
}

class CarsScreen extends StatelessWidget {
  const CarsScreen({super.key, required this.repository});

  final CarsRepository repository;

  @override
  Widget build(BuildContext context) => ListenableBuilder(
    listenable: repository.cars,
    builder: (context, _) => Text('${repository.cars.value.length} cars'),
  );
}
```

```dart
/// Presentation state for the cars screen, derived from the repository.
class CarsViewModel extends ChangeNotifier {
  CarsViewModel(this._repository) {
    _repository.cars.addListener(notifyListeners);
  }

  final CarsRepository _repository;

  int get carCount => _repository.cars.value.length;

  @override
  void dispose() {
    _repository.cars.removeListener(notifyListeners);
    super.dispose();
  }
}

/// The root widget. Owns the repository and view model, and ties sync and
/// shutdown to the app lifecycle.
class CarsApp extends StatefulWidget {
  const CarsApp({
    super.key,
    required this.service,
    this.syncInBackground = false,
  });

  final DittoService service;

  /// Whether sync keeps running while a mobile app is paused.
  final bool syncInBackground;

  @override
  State<CarsApp> createState() => _CarsAppState();
}

class _CarsAppState extends State<CarsApp> {
  late final _repository = CarsRepository(widget.service.ditto);
  late final _viewModel = CarsViewModel(_repository);
  late final AppLifecycleListener _lifecycle;

  // Cancels the observer once, on exit or unmount, whichever comes first.
  late final Future<void> _stopObserving = _repository.dispose();

  @override
  void initState() {
    super.initState();
    final sync = widget.service.ditto.sync;
    _lifecycle = AppLifecycleListener(
      // Called on iOS and Android only.
      onPause: widget.syncInBackground ? null : sync.stop,
      onRestart: widget.syncInBackground ? null : sync.start,
      // Called only for exits the platform lets the app cancel (desktop).
      onExitRequested: () async {
        await _stopObserving;
        await widget.service.close();
        return AppExitResponse.exit;
      },
    );
  }

  @override
  void dispose() {
    _lifecycle.dispose();
    _viewModel.dispose();
    unawaited(_stopObserving);
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => Directionality(
    // Your WidgetsApp or MaterialApp goes here.
    textDirection: TextDirection.ltr,
    child: CarsPage(viewModel: _viewModel),
  );
}

class CarsPage extends StatelessWidget {
  const CarsPage({super.key, required this.viewModel});

  final CarsViewModel viewModel;

  @override
  Widget build(BuildContext context) => ListenableBuilder(
    listenable: viewModel,
    builder: (context, _) => Text('${viewModel.carCount} cars'),
  );
}
```

Imports for these blocks: `dart:async`, `dart:ui` (`AppExitResponse`),
`package:ditto_live/ditto_live.dart` and `package:flutter/widgets.dart`. Use your
`WidgetsApp` or `MaterialApp` where the comment says; Flutter 3.50.0 deprecates
`package:flutter/material.dart` in favour of `package:material_ui`, so these samples use
widgets only.

Executed (macOS desktop, debug, Flutter 3.50.0, ditto_live 5.0.4, 5.1.0 and 5.2.0): the
page shows `1 cars` after an insert; leaving and re-entering a `CarsScreen` throws
nothing and keeps observing; lifecycle states driven through the test binding stop and
restart sync, and an exit request returns `AppExitResponse.exit` with Ditto closed.

Rules:

- **No `StreamBuilder` over an observer's raw `changes`.** The stream is
  single-subscription: building the screen a second time throws
  `StateError: Stream has already been listened to.`, and disposing the `StreamBuilder`
  cancels its listener but leaves a V1 observer running (executed, all three lines).
  Wrong and right forms: [anti-patterns.md](anti-patterns.md).
- **`late final` fields, not `build`, create repositories and view models**, so a
  rebuild never registers a second observer.
- **`Provider` only when the app already uses it.** Then hand over the existing object
  with `Provider<CarsViewModel>.value(value: viewModel, child: …)`, and in `build` use
  `context.watch`; `context.read` belongs in callbacks, since in `build` it never
  rebuilds. Otherwise, pass objects through constructors as above.

## Small-app variant

For one screen that owns one query, the `State` can hold the observer. `dispose()` cannot
await, so it starts the listener's cancel and cancels the observer; `mounted` guards
`setState`. Executed with the probes above: re-entering the screen throws nothing.

<!-- snippet: flutter-widgets-3 -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```dart
/// A small app: the screen owns its observer.
class CarCountScreen extends StatefulWidget {
  const CarCountScreen({super.key, required this.ditto});

  final Ditto ditto;

  @override
  State<CarCountScreen> createState() => _CarCountScreenState();
}

class _CarCountScreenState extends State<CarCountScreen> {
  late final StoreObserver _observer;
  late final StreamSubscription<QueryResult> _changes;
  var _count = 0;

  @override
  void initState() {
    super.initState();
    // No onChange: this state holds the one `changes` listener.
    _observer = widget.ditto.store.registerObserver('SELECT * FROM cars');
    _changes = _observer.changes.listen((result) {
      if (!mounted) return;
      setState(() => _count = result.items.length);
    });
  }

  @override
  void dispose() {
    // dispose() cannot await. Ditto must still be open here.
    unawaited(_changes.cancel());
    _observer.cancel();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) => Text('$_count cars');
}
```
<!-- /snippet -->

Imports: `dart:async`, `package:ditto_live/ditto_live.dart`, `package:flutter/widgets.dart`.

## App lifecycle

`AppLifecycleListener` callbacks per platform, from Flutter's API docs
(`widgets/app_lifecycle_listener.dart` and `services/binding.dart`, Flutter 3.50.0):

| Callback | iOS, Android | macOS, Windows, Linux | Web |
|---|---|---|---|
| `onInactive`, `onResume` | yes | yes (focus lost or regained) | yes (tab focus) |
| `onHide`, `onShow` | yes | yes (minimized or shown) | yes (tab hidden or shown) |
| `onPause`, `onRestart` | yes | never | never |
| `onDetach` | yes | never | never |
| `onExitRequested` | no | only for exits the platform lets the app cancel; Flutter documents macOS and Linux | no |

- **Stop sync on pause *if the app does not need background sync*:**
  `onPause: sync.stop`, `onRestart: sync.start`, as `CarsApp` does unless
  `syncInBackground`. Background sync needs platform declarations: the
  `native-app-config` skill if installed, otherwise
  <https://docs.ditto.live/sdk/latest/install-guides/flutter>.
- **Close on exit, desktop only:**
  `onExitRequested: () async { await service.close(); return AppExitResponse.exit; }`,
  after cancelling observers. Never `close()` in `onPause` or `onDetach`.
- **Dispose the listener** in the owning `State.dispose()`.

The callbacks were executed only through the test binding; on-device delivery per
platform is Flutter's documented behaviour, not observed here.

## Hot restart

| Action | What happens to Ditto | Do |
|---|---|---|
| Hot reload (`r`) | Keeps running; the install guide calls it "fully compatible" (not executed here) | nothing |
| Hot restart (`R`), native | The old instance is never closed and keeps running and syncing. Re-opening its directory fails: 5.2.0 `DittoException(File already locked, … retried 5 times. …)`; 5.1.0 hangs | debug-only random directory, or a full restart |
| Hot restart (`R`), web | `Ditto.open` fails at once with `File already locked` | restart the dev server, or the debug-only random directory |
| Full restart (stop, run again) | The process ends; the next launch opens the directory with its data intact | — |

Executed on macOS and Chrome with 5.2.0 debug builds. A hot restart resets every Dart
static, so an app-scoped holder cannot pass the old instance to the new `main()`, and
retrying `Ditto.open` for 20 s never succeeded.

The install guide's fix (<https://docs.ditto.live/sdk/latest/install-guides/flutter#step-8-working-with-hot-restart>):
a new persistence directory per debug launch. Pass the result as `config` to
`DittoService.open`:

```dart
import 'package:ditto_live/ditto_live.dart';
import 'package:flutter/foundation.dart';

/// Debug builds only: a new directory per launch, so a hot restart never
/// re-opens the directory the orphaned instance holds. Release and profile
/// builds pass null, the SDK default `ditto-{databaseID}`.
DittoConfig appConfig() => DittoConfig(
  databaseID: 'REPLACE_ME_WITH_YOUR_DATABASE_ID',
  connect: const DittoConfigConnectServer(url: 'REPLACE_ME_WITH_YOUR_URL'),
  persistenceDirectory: kDebugMode
      ? 'ditto-debug-${DateTime.now().microsecondsSinceEpoch}'
      : null,
);
```

- **Production keeps the SDK default: pass no `persistenceDirectory`.** The install
  guide's version switches production to `'ditto'`, which is not the v5 default
  `ditto-{databaseID}`: an app already shipped with the default would open an empty
  store and leave its data behind.
- Each debug launch starts with an empty store; data written before a hot restart stays
  in the earlier directory. Executed (macOS, Chrome): the randomized directory opens after
  `R`. Nothing deletes the old debug directories.
- When you need persistence across a restart, do a full restart.
- **Avoid V2 and presence observers in sessions you hot-restart.** An orphaned V2
  observer crashed the app on the next remote change (`EXC_BAD_ACCESS (SIGBUS)` or
  `SIGSEGV`, thread `live query callback 2`; 5.1.0 and 5.2.0, macOS debug); on 5.1.0 a
  V1 observer did too, on 5.0.4 and 5.2.0 V1 did not. On 5.2.0, V2 observers and
  presence observers deliver through a `NativeCallable`
  (`lib/src/bridge/native/store.dart`, `presence.dart` @ `sdk-release-5.2.0`) whose Dart
  side the restart discards; that this causes the crash is an inference.

## Diffing for animated lists

`Differ().diff(items)` compares a result with the previous one passed to the same
`Differ`, matching items by `_id`, and returns a `Diff` of `insertions`, `deletions`,
`updates` (index sets) and `moves` (`DiffMove` `from`/`to`): what `AnimatedList` needs.
Pass `result.items.toList()` from the repository's listener; the first call reports
every item as inserted (`lib/src/differ.dart` @ `sdk-release-5.2.0`, also in 5.0.4; not
executed).
