## CAP-12 Attachments

| API | Shape |
|---|---|
| `ditto.store.newAttachment` | `Future<Attachment> newAttachment(StringOrData pathOrData, [AttachmentMetadata? metadata])`: a file path (`String`) or bytes (`Uint8List`); metadata is **positional** |
| `AttachmentMetadata` | `AttachmentMetadata(Map<String, String> metadata)`: a wrapper, not a map; read back as `.metadata` |
| `Attachment` | `id`, `len`, `metadata`, `Future<Uint8List> data`, `Future<void> copyToPath(String destination)` |
| `ditto.store.fetchAttachment` | `AttachmentFetcher fetchAttachment(Map<String, dynamic> token, void Function(AttachmentFetchEvent) onFetchEvent)` |
| `AttachmentFetcher` | `Future<Attachment?> attachment`, `isStopped`, `stop()` |
| `AttachmentFetchEvent` | `AttachmentFetchEventCompleted(attachment)`, `AttachmentFetchEventProgress(downloadedBytes, totalBytes)`, `AttachmentFetchEventDeleted()` |
| `ditto.store.attachmentFetchers` | `Set<AttachmentFetcher>` of fetches still running |

The same on 4.14.7, 5.0.4, 5.1.0 and 5.2.0 (`lib/src/store/store.dart`,
`attachment.dart`, `attachment_fetcher.dart`, `shared/attachment_metadata.dart` at each
tag). Imports for these blocks: `dart:async`, `dart:typed_data`,
`package:ditto_live/ditto_live.dart`.

/// Creates an attachment from bytes, on every platform. The metadata is an
/// optional positional AttachmentMetadata that wraps a String map.
Future<Attachment> attachPhotoBytes(Ditto ditto, Uint8List jpeg) =>
    ditto.store.newAttachment(jpeg, AttachmentMetadata({'name': 'photo.jpg'}));

/// Creates an attachment from a file path. Not on web, which has no files.
Future<Attachment> attachPhotoFile(Ditto ditto, String path) =>
    ditto.store.newAttachment(path);

```dart
/// Stores [photo] on the car [carId] and returns the attachment token that
/// a query returns for it.
Future<Map<String, dynamic>> savePhoto(
  Ditto ditto,
  String carId,
  Attachment photo,
) async {
  await ditto.store.execute(
    'INSERT INTO COLLECTION cars (photo ATTACHMENT) DOCUMENTS (:car)',
    arguments: {
      'car': {'_id': carId, 'photo': photo},
    },
  );
  final result = await ditto.store.execute(
    'SELECT * FROM COLLECTION cars (photo ATTACHMENT) WHERE _id = :id',
    arguments: {'id': carId},
  );
  return result.items.first.value['photo'] as Map<String, dynamic>;
}

/// Fetches the attachment behind [token]. The future completes with it; the
/// fetcher stops by itself once the fetch completes.
(AttachmentFetcher, Future<Attachment>) fetchPhoto(
  Ditto ditto,
  Map<String, dynamic> token,
) {
  final fetched = Completer<Attachment>();
  final fetcher = ditto.store.fetchAttachment(token, (event) {
    switch (event) {
      case AttachmentFetchEventCompleted(:final attachment):
        fetched.complete(attachment);
      case AttachmentFetchEventProgress():
        break; // downloadedBytes / totalBytes
      case AttachmentFetchEventDeleted():
        fetched.completeError(StateError('attachment deleted'));
    }
  });
  return (fetcher, fetched.future);
}
```

Executed (macOS, debug, 5.0.4, 5.1.0 and 5.2.0):

- Bytes and a file path both produce an `Attachment` with the right `len`; the bytes
  one has the metadata `{'name': 'photo.jpg'}`, the path one empty metadata, and
  `await attachment.data` returns the file's bytes.
- `newAttachment(42)` (neither a path nor bytes) fails its `Future` with a
  `DittoException`.
- **Store it by putting the `Attachment` object in the document argument** and naming
  the field in the collection definition: `INSERT INTO COLLECTION cars (photo ATTACHMENT) DOCUMENTS (:car)`.
  Reading it back with `SELECT * FROM COLLECTION cars (photo ATTACHMENT) …` gives the
  field as a token, a `Map<String, dynamic>`, which is what `fetchAttachment` takes.
- There is no table or schema to create first. `newAttachment` copies the file or
  bytes into Ditto's store; the document holds only the token.

A relative path is resolved against the persistence directory, and a missing or
unreadable file fails the `Future` (dartdoc of `newAttachment` @ `sdk-release-5.2.0`;
not executed). The dartdoc's own example passes the `execute` arguments positionally,
which does not compile; use `arguments:`.

### Fetch

Attachments do not travel with their document: a peer that syncs the document gets the
token, and the bytes move only when that peer calls `fetchAttachment`
(<https://docs.ditto.live/sdk/latest/crud/working-with-attachments>).

- **Events:** any number of `AttachmentFetchEventProgress`, then at most one
  `AttachmentFetchEventCompleted` or `AttachmentFetchEventDeleted` (dartdoc). Switch on
  the event type, as `fetchPhoto` does.
- **The fetcher stops itself** on the terminal event. Executed: `isStopped` was `false`
  while fetching, `true` after `Completed`, and the fetcher had left
  `ditto.store.attachmentFetchers`. Calling `stop()` is for abandoning a fetch.
- **Dropping the fetcher does not stop the fetch:** the store keeps it in
  `attachmentFetchers` until it ends (source, `store.dart` @ `sdk-release-5.2.0`). To
  abandon it, keep the handle and call `stop()`, for example from the owner's
  `dispose`.
- **`fetcher.attachment`**, the fetcher's own `Future`, completes on `Completed` and
  fails with a `DittoError` (`The attachment was deleted while being fetched.`) on
  `Deleted`; after `stop()` it never completes (source). Code that relies on the
  callback, as `fetchPhoto` does, should also call `fetcher.attachment.ignore()`, so
  that a deletion is not reported as an unhandled async error (inference from the
  source; not executed).
- `Attachment.data` reads the bytes; `copyToPath(destination)` writes them to a file
  you own and must delete yourself.

### Web

Bytes only: `newAttachment(path)` fails its `Future` with
`DittoException(Creating attachments from files is not supported on Flutter Web.)` and
`copyToPath` with `DittoException(Retrieving a filesystem path for attachments is not supported on the Web.)`;
`newAttachment(Uint8List)` and `Attachment.data` work (executed, Chrome, debug, 5.0.4
to 5.2.0). The store is in memory, so attachments go with it on a page load:
[web.md](web.md#web-differences).
