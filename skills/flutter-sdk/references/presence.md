## CAP-13 Presence and connection requests

| API | Shape |
|---|---|
| `ditto.presence.graph` | `PresenceGraph`: a snapshot; `localPeer` (`Peer`) and `remotePeers` (`Set<Peer>`) |
| `ditto.presence.observe` | `PresenceObserver observe(void Function(PresenceGraph graph) onChange)`; stop with `observer.stop()` |
| `Peer` | `peerKey` (`String`), `deviceName`, `os`, `isConnectedToDittoServer`, `isCompatible`, `dittoSdkVersion`, `connections` (`List<Connection>`), `peerMetadata`, `identityServiceMetadata` |
| `Connection` | `id`, `peer1`, `peer2` (peer keys), `connectionType` (`ConnectionType`) |
| `ditto.presence.peerMetadata` | `Map<String, dynamic>` get/set; `peerMetadataJsonString` is the same as JSON |
| `ditto.presence.connectionRequestHandler` | `ConnectionRequestHandler?`, a `Future<ConnectionRequestAuthorization> Function(ConnectionRequest)` |

From `lib/src/presence/presence.dart` and `presence_graph.dart` @ `sdk-release-5.2.0`;
the same members on 5.0.4. `PresenceGraph`, `Peer` and `Connection` have `toJson()`
for diagnostics. There is no distance estimate: v5 removed
`Connection.approximateDistanceInMeters`
(<https://docs.ditto.live/sdk/latest/migration-guides/flutter-v4>).
Imports for the blocks below: `dart:async`, `package:ditto_live/ditto_live.dart`.

### Observing the graph

<!-- snippet: flutter-presence-1 -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```dart
/// Completes with the remote peer [peerKey] once presence reports it. Stop
/// the returned observer when you no longer need it.
(PresenceObserver, Future<Peer>) waitForPeer(Ditto ditto, String peerKey) {
  final seen = Completer<Peer>();
  final observer = ditto.presence.observe((graph) {
    for (final peer in graph.remotePeers) {
      if (peer.peerKey == peerKey && !seen.isCompleted) seen.complete(peer);
    }
  });
  return (observer, seen.future);
}
```
<!-- /snippet -->

- The callback runs once soon after `observe` with the current graph, then whenever
  peers or connections change (dartdoc; the 5.2.0 code schedules the first delivery on
  the next event-loop turn). It runs on the isolate that called `observe`.
- **Retain the `PresenceObserver` and call `stop()`**: `stop`, not `cancel`. Dropping it
  does not stop it: on 5.2.0 the `Presence` object keeps every callback until `stop()`
  or `close()` (source). An exception thrown in the callback is logged by Ditto, not
  rethrown (5.2.0 source).
- `remotePeers` is a `Set`: no index access.
- Presence observers are delivered through a `NativeCallable` (5.2.0 source), the
  mechanism behind the hot-restart crashes of V2 observers; that presence observers
  crash the same way was not run. Avoid them in sessions you hot-restart:
  [widget-integration.md](widget-integration.md#hot-restart).

### Connection types

`ConnectionType` has four values on 5.0.x (`bluetooth`, `accessPoint`, `p2pWifi`,
`webSocket`) and five from 5.1.0, which adds `multicast` (executed: the probes assert
`ConnectionType.values` has length 4 on 5.0.4 and 5 on 5.1.0 and 5.2.0). An exhaustive
`switch` over all five does not compile against 5.0.x; one over four does not compile
against 5.1.0+ without a wildcard arm. For 5.1.0+:

  ConnectionType.bluetooth => 'Bluetooth',

  ConnectionType.multicast => 'Multicast', // 5.1.0+

### Peer metadata

`ditto.presence.peerMetadata = {'role': 'driver'}` publishes a JSON object to other
peers, who read it as `Peer.peerMetadata` in the graph and as
`ConnectionRequest.peerMetadata`. The setter throws for invalid JSON, a value that is
not an object, or more than 4 KB encoded (dartdoc, `presence.dart` @
`sdk-release-5.2.0`; not executed). It reaches other peers with presence updates, not
instantly.

### Connection request handler

<!-- snippet: flutter-presence-2 -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```dart
/// Refuses connections from [blockedPeerKey] and accepts every other peer.
/// Install with `ditto.presence.connectionRequestHandler = blockPeer(key)`.
/// A handler that throws refuses the connection too.
ConnectionRequestHandler blockPeer(String blockedPeerKey) =>
    (request) async => request.peerKey == blockedPeerKey
    ? ConnectionRequestAuthorization.deny
    : ConnectionRequestAuthorization.allow;
```
<!-- /snippet -->

- With no handler every connection is allowed. A `ConnectionRequest` has `peerKey`,
  `connectionType`, `peerMetadata` and `identityServiceMetadata`; expect one request
  per transport between the same two peers (source and dartdoc, `presence.dart` @
  `sdk-release-5.2.0`).
- **A handler that throws, or takes longer than about 10 s, denies the request**
  (dartdoc: "currently times out after 10 seconds"). Executed (macOS, debug, 5.0.4,
  5.1.0, 5.2.0, two instances over TCP loopback): the connecting peer's handler was
  called within 20 s with the listening peer's `peerKey`; when it denied, or threw, the
  listener's document did not reach it in a 5 s window.
- Set it before `sync.start()`, as the probes do, so the first connections are
  filtered. After `close()` the SDK answers `deny` without calling it, and setting
  `null` allows every request again (source).

### Two peers in one process

Two instances in their own directories can sync over TCP loopback: one listens, the
other connects (`listenForPeers`, `connectToPeer`). Executed (macOS, 5.0.4 to 5.2.0):
with every peer-to-peer transport off, the connecting peer saw the listener in
presence within 20 s, and a document written on the listener reached the connector
through its subscription. Use this in tests; it needs no Bluetooth or LAN permission.

<!-- snippet: flutter-presence-3 -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```dart
/// Accepts TCP connections from other peers on [port]. The default
/// [interfaceIP], `[::]`, is the SDK's: every interface.
void listenForPeers(Ditto ditto, int port, {String interfaceIP = '[::]'}) {
  ditto.updateTransportConfig((config) {
    config.listen.tcp
      ..isEnabled = true
      ..interfaceIP = interfaceIP
      ..port = port;
  });
}

/// Connects to a peer that listens at [hostAndPort], e.g. `10.0.0.5:4040`.
void connectToPeer(Ditto ditto, String hostAndPort) {
  ditto.updateTransportConfig((config) {
    config.connect.tcpServers.add(hostAndPort);
  });
}
```
