## CAP-08 Executing DQL

`Future<QueryResult> execute(String query, {Map<String, dynamic> arguments = const {}})`
on `ditto.store`, the same on every line (`lib/src/store/store.dart` @
`sdk-release-5.2.0`, `sdk-release-5.1.0`, ditto_live 5.0.4, `flutter/ditto_live` @
`sdk-release-4.14.7`). Imports for the blocks in this file:
`package:ditto_live/ditto_live.dart`.

<!-- snippet: flutter-store-1 -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```dart
/// Inserts [car] and returns the IDs of the documents the statement changed.
/// IDs are `dynamic`: an `_id` can be a string, number, map or other value.
Future<List<dynamic>> insertCar(Ditto ditto, Map<String, dynamic> car) async {
  final result = await ditto.store.execute(
    'INSERT INTO cars DOCUMENTS (:car)',
    arguments: {'car': car},
  );
  return result.mutatedDocumentIDs(); // a method, not a getter
}
```
<!-- /snippet -->

- **`arguments:` is a named parameter**, a `Map<String, dynamic>` whose keys match the
  `:name` placeholders. Values are encoded as CBOR: maps with `String` keys, lists,
  strings, numbers, booleans, `null`, and `Attachment` objects
  ([attachments.md](attachments.md#cap-12-attachments)). Never build the query string
  from values; bind them.
- **Always `await` it**, or hand the `Future` to something that does; the
  `unawaited_futures` lint flags a dropped one.
- `execute` returns only what is in the local store. It does not wait for sync; to see
  data as it arrives, observe it ([observers.md](observers.md#cap-11-observers-and-live-queries))
  (dartdoc).
- Where the work runs differs per line (a worker isolate on 5.1.0+ native, a
  per-call isolate on 5.0.x, the calling isolate on web):
  [concurrency.md](concurrency.md#where-each-callback-runs). On web, decode only the
  items you render: [web.md](web.md#execute-on-the-main-thread).

### Results

| Member | Type | Notes |
|---|---|---|
| `items` | `Iterable<QueryResultItem>` | Not a `List` (executed). Index-free; call `.toList()` before storing it |
| `item.value` | `Map<String, dynamic>` | The document, decoded from JSON on first access and cached |
| `item.jsonString`, `item.cborBytes` | `String`, `Uint8List` | The raw forms, for passing on without decoding |
| `mutatedDocumentIDs()` | `List<dynamic>` | A **method**. IDs may be strings, numbers, maps or lists. Not cached: call once |
| `commitID` | `int?` | The local commit of a mutating statement; `null` for a `SELECT` (executed): [sync.md](sync.md#cap-14-sync-status) |

From `lib/src/store/execute.dart` @ `sdk-release-5.2.0` (`value` uses `jsonDecode`, so
numbers arrive as `int` or `double` and nested objects as `Map<String, dynamic>`).
For a typed model, map `item.value` through your own `fromJson`; the SDK has no
codegen or typed decoding.

```dart
import 'package:ditto_live/ditto_live.dart';

class Car {
  const Car({required this.id, required this.color});

  factory Car.fromJson(Map<String, dynamic> json) =>
      Car(id: json['_id'] as String, color: json['color'] as String);

  final String id;
  final String color;
}

/// Reads the cars of [color] as typed values.
Future<List<Car>> carsOfColor(Ditto ditto, String color) async {
  final result = await ditto.store.execute(
    'SELECT * FROM cars WHERE color = :color',
    arguments: {'color': color},
  );
  return result.items.map((item) => Car.fromJson(item.value)).toList();
}
```

### Errors from execute

`execute` is `async`: a rejected statement fails the returned `Future` with a
`DittoException`; nothing is thrown at the call. A syntax error, executed (macOS,
5.0.4, 5.1.0 and 5.2.0, the same text on each):

```text
DittoException(<dql> Invalid query: `DQL parser error: Unexpected token SELEC at line 1 column 1 near "SELEC * FROM"; expected a DQL statement`. For more information on Ditto's query language see: https://ditto.com/link/dql-guide)
```

After `close()` the `Future` fails with `DittoClosedException`
([connect.md](connect.md#cap-05-lifecycle)). Handling both error families:
[errors.md](errors.md#cap-16-error-handling).

## CAP-09 Transactions

`Future<T> transaction<T>(Future<T> Function(Transaction) callback, {bool isReadOnly = false, String? hint})`
on `ditto.store`; `Transaction.execute` has the same shape as `store.execute`
(`store.dart`, `transaction.dart` @ `sdk-release-5.2.0`; the same in 5.1.0 and 5.0.4).

<!-- snippet: flutter-store-2 -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```dart
/// Inserts [order] and its [lines] together, or neither.
Future<void> saveOrder(
  Ditto ditto,
  Map<String, dynamic> order,
  List<Map<String, dynamic>> lines,
) async {
  await ditto.store.transaction((tx) async {
    await tx.execute(
      'INSERT INTO orders DOCUMENTS (:order)',
      arguments: {'order': order},
    );
    if (lines.isEmpty) {
      // Any exception thrown by the callback rolls the transaction back and
      // is rethrown to the caller of transaction().
      throw ArgumentError.value(lines, 'lines', 'an order needs a line');
    }
    for (final line in lines) {
      await tx.execute(
        'INSERT INTO order_lines DOCUMENTS (:line)',
        arguments: {'line': line},
      );
    }
  });
}
```
<!-- /snippet -->

<!-- snippet: flutter-store-3 -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```dart
/// Inserts [car] only if no car has the same plate; returns whether it did.
Future<bool> insertCarIfNewPlate(Ditto ditto, Map<String, dynamic> car) async {
  final action = await ditto.store.transaction((tx) async {
    await tx.execute(
      'INSERT INTO cars DOCUMENTS (:car)',
      arguments: {'car': car},
    );
    final same = await tx.execute(
      'SELECT * FROM cars WHERE plate = :plate',
      arguments: {'plate': car['plate']},
    );
    // Returning rollback discards the writes; any other value commits.
    return same.items.length > 1
        ? TransactionCompletionAction.rollback
        : TransactionCompletionAction.commit;
  });
  return action == TransactionCompletionAction.commit;
}
```
<!-- /snippet -->

Executed (macOS, 5.0.4, 5.1.0, 5.2.0):

- **A throw rolls back** and is rethrown to the caller of `transaction()`: after
  `saveOrder` threw `ArgumentError`, `orders` held 0 documents.
- **Returning `TransactionCompletionAction.rollback`** discards the writes; any other
  return value commits and becomes `transaction()`'s result.
- **`ditto.store.execute` inside the callback fails** with a `DittoException` that
  starts `Attempting to use `ditto.store.execute` while in a transaction scope`. Use
  the `tx` parameter.
- **A mutating statement in an `isReadOnly: true` transaction fails** with
  `DittoException(<store> A mutating DQL query was attempted using a read-only transaction.)`
  and writes nothing.

From the dartdoc: one read-write transaction runs at a time and others wait for it;
read-only transactions run concurrently; `hint` is logged; the `Transaction` object is
valid only inside the callback, so never store it.

**Validate before you open the transaction.** `saveOrder` checks `lines` inside the
callback only to show the rollback. In an app, reject bad input before calling
`transaction()`, so that no read-write transaction is held open, blocking every other,
for work that is bound to fail. Keep the callback to DQL calls; no network or UI work.

## CAP-10 Indexing

Indexes are DQL statements sent through `execute`; there is no Dart index API.

<!-- snippet: flutter-store-4 -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```dart
/// Speeds up queries that filter cars by color.
Future<void> createColorIndex(Ditto ditto) => ditto.store.execute(
  'CREATE INDEX IF NOT EXISTS cars_color ON cars (color)',
);
```
<!-- /snippet -->

Executed (macOS, 5.0.4, 5.1.0, 5.2.0): `CREATE INDEX IF NOT EXISTS` succeeds. Run it once
at startup, after `Ditto.open` and before the screens that query. Which queries an index
serves, composite indexes (5.1.0+), `DROP INDEX`, listing indexes, and `EXPLAIN`/`ADVISE`
are DQL: the `dql` skill if installed, otherwise <https://docs.ditto.live/dql/indexing>.
Their results come back as ordinary `QueryResult` items.

## CAP-17 Device storage management

`EVICT` removes documents from the local store only, unlike `DELETE`, which replicates.
It goes through the same `execute` call:

<!-- snippet: flutter-store-5 -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```dart
/// Evicts the cars of [color] from the local store; returns their IDs.
Future<List<dynamic>> evictCars(Ditto ditto, String color) async {
  final evicted = await ditto.store.execute(
    'EVICT FROM cars WHERE color = :color',
    arguments: {'color': color},
  );
  return evicted.mutatedDocumentIDs();
}
```
<!-- /snippet -->

Executed (macOS, 5.0.4, 5.1.0, 5.2.0): `evictCars` returned `['car-1']` and the
collection was empty afterwards (no peers, so no subscription interplay). The docs
say to cancel the subscriptions that match documents before evicting them, so that
Ditto is not purging documents it is still syncing. That interplay and eviction
strategy are concept material: the `sync-subscriptions` skill if installed, otherwise
<https://docs.ditto.live/sdk/latest/sync/device-storage-management>. The
Flutter SDK has no disk-usage API ([observability.md](observability.md#disk-usage)).
