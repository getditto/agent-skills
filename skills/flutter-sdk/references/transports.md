## CAP-06 Customizing transports

**Read** with `ditto.transportConfig` (an immutable `TransportConfig`). **Change** with
`ditto.updateTransportConfig((config) { … })`: the callback gets a mutable
`TransportConfigBuilder` copy of the current config, and the result replaces it when the
callback returns. It returns `void`; do not `await` it. Assigning
`ditto.transportConfig = …` replaces the whole config
(`sdks/flutter/ditto_live/lib/src/ditto.dart:226-244` @ `sdk-release-5.2.0`).

Builder fields (`transport_config.dart` @ `sdk-release-5.2.0`; all exist on 5.0.4 except
`multicastBeta`):

| Path | Fields |
|---|---|
| `config.peerToPeer.bluetoothLE` | `isEnabled` |
| `config.peerToPeer.lan` | `isEnabled`, `isMdnsEnabled` |
| `config.peerToPeer.awdl` | `isEnabled` (iOS, macOS) |
| `config.peerToPeer.wifiAware` | `isEnabled` (Android) |
| `config.peerToPeer.multicastBeta` (5.1.0+) | `isEnabled`, `groupAddress`, `port`, `interfaceName`; private beta, off by default |
| `config.connect` | `tcpServers` and `webSocketUrls` (`Set<String>`), `retryInterval` (`Duration`) |
| `config.listen.tcp` | `isEnabled`, `interfaceIP`, `port` |
| `config.listen.http` | `isEnabled`, `interfaceIP`, `port`, `websocketSync`, `tlsKeyPath`, `tlsCertificatePath` |
| `config.global` | `syncGroup`, `routingHint` |

**Turn peer-to-peer off transport by transport.** On 5.0.x,
`setAllPeerToPeerEnabled(false)` and `withAllPeerToPeerEnabled(false)` set Bluetooth LE
and LAN to the argument but turn the platform's Wi-Fi transport **on**: AWDL on iOS and
macOS, Wi-Fi Aware on Android. On Linux and Windows they honour the argument, and on web
they do nothing (`lib/src/transport_config.dart:170-183`, ditto_live 5.0.4 from pub.dev;
5.1.0 assigns the argument everywhere). Not executed. This function runs before every
probe of the fixture (executed: all four read back `false`, macOS, 5.0.4 to 5.2.0):

Imports: `package:ditto_live/ditto_live.dart`.

<!-- snippet: flutter-transports-1 -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```dart
/// Turns off every peer-to-peer transport the 5.0 API can name, one by one:
/// on 5.0.x, `setAllPeerToPeerEnabled(false)` leaves AWDL and Wi-Fi Aware on.
/// Multicast (5.1+) is off by default.
void disablePeerToPeer(Ditto ditto) {
  // updateTransportConfig returns void: there is nothing to await.
  ditto.updateTransportConfig((config) {
    config.peerToPeer.bluetoothLE.isEnabled = false;
    config.peerToPeer.lan.isEnabled = false;
    config.peerToPeer.awdl.isEnabled = false;
    config.peerToPeer.wifiAware.isEnabled = false;
  });
}
```
<!-- /snippet -->

**Enable peer-to-peer only off the web**, with `kIsWeb` first and then
`Ditto.currentPlatform`: the executed gate is `enablePeerToPeer` in
[web.md](web.md#code-that-compiles-on-web), and the rule is in
[setup.md](setup.md#gate-platform-code-with-kisweb-then-dittocurrentplatform). On web, an
enabled peer-to-peer transport throws `DittoException` from `sync.start()` on 5.2.0 and
from `updateTransportConfig` itself on 5.0.4 and 5.1.0, while `setAllPeerToPeerEnabled(true)`
and `withAllPeerToPeerEnabled(true)` leave every transport off and `sync.start()`
succeeds (executed, Chrome, 5.0.4 to 5.2.0).

**Connect and listen** over TCP, as the two-peer presence probes do on loopback
(executed, macOS, 5.0.4 to 5.2.0): `listenForPeers` and `connectToPeer` in
[presence.md](presence.md#cap-13-presence-and-connection-requests).

**Changing the config while syncing** is allowed; the dartdoc says changes "are applied
asynchronously and do not throw on invalid input"
(`ditto.dart:135-140` @ `sdk-release-5.2.0`), except the web case above. Multicast on iOS and Android takes effect
only after `sync.stop()` and the next `sync.start()` (dartdoc of `MulticastBetaConfig`).

### Transport conditions (5.1.0+)

`ditto.observeTransportConditions(onChange)` returns a `TransportConditionsObserver`:
`onChange` is a required positional `void Function(TransportConditionEvent)`, `changes`
is a broadcast `Stream<TransportConditionEvent>`, and `stop()` ends it (also ended by
`close()`). Each event has a `condition` (`TransportCondition`) and a `source`
(`TransportConditionSource`) (`transport_conditions.dart` @ `sdk-release-5.2.0`). What
each value means is `ditto-mesh-networking`'s, otherwise
<https://docs.ditto.live/sdk/latest/sync/customizing-transport-configurations>.

<!-- dart-version: 5.1 -->
```dart
import 'dart:developer';

import 'package:ditto_live/ditto_live.dart';

/// 5.1.0+: logs every condition other than `ok` until the returned
/// observer is stopped.
TransportConditionsObserver logTransportConditions(Ditto ditto) =>
    ditto.observeTransportConditions((event) {
      if (event.condition != TransportCondition.ok) {
        log('${event.source}: ${event.condition}', name: 'ditto');
      }
    });
```

Executed (macOS, 5.1.0 and 5.2.0): with every peer-to-peer transport off,
`sync.start()` produced no event within 5 s, on the callback or the stream. Do not wait
for a first event.
