## CAP-03 Connecting: config, opening, persistence directory

<!-- snippet: rust-open-config -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```rust
async fn open_ditto() -> Result<Ditto, DittoError> {
    let mut config = DittoConfig::new(
        "REPLACE_ME_WITH_YOUR_DATABASE_ID",
        DittoConfigConnect::SmallPeersOnly { private_key: None },
    )
    .with_persistence_directory("/var/lib/my-app/ditto");
    // Optional overrides, applied before Ditto starts its subsystems.
    config.system_parameters.insert(
        "REPLACE_ME_WITH_A_PARAMETER_NAME".into(),
        serde_json::json!(true),
    );
    Ditto::open(config).await
}
```
<!-- /snippet -->

- `DittoConfig` is `#[non_exhaustive]`: build it with `DittoConfig::new(database_id,
  connect)`, then set fields. A struct literal is `E0639`.
- Fields: `database_id: String`, `connect: DittoConfigConnect`,
  `persistence_directory: Option<PathBuf>`, `system_parameters: HashMap<String,
  serde_json::Value>`. The hidden `experimental.passphrase` is rejected when set: the
  Rust SDK has no encryption at rest.
- `system_parameters`: JSON `null` anywhere fails `ErrorKind::InvalidInput` before Ditto
  is touched. Unknown names or bad values fail `open` with
  `CoreApi(ValidationInvalidDittoConfig)`. Parameter names are not covered here; see
  <https://docs.ditto.live/sdk/latest/sync/using-alter-system>.
- `Ditto::open(config).await` is the default. `Ditto::open_sync(config)` blocks the caller
  and exists for non-async code. Neither may be cancelled
  ([concurrency.md](concurrency.md#cancellation-safety)).
- `DittoConfig` derives `Serialize`/`Deserialize` (tagged `connect.type` =
  `small_peers_only` | `server`), so loading it from a config file works.
- After opening: `ditto.config()` (effective config), `ditto.absolute_persistence_directory()`,
  `Ditto::version()` (e.g. `"5.2.0"`), `ditto.set_device_name("…")` (call before
  `sync().start()`; it appears in peers' presence graphs).

## Persistence directory

- **Set it explicitly in every deployed app.** The default is
  `<directory of the executable>/ditto-<database id, lowercased>` — under `cargo run`
  that is inside `target/debug/`, and `cargo clean` deletes it.
- A relative path resolves against the executable's directory, not the working
  directory. Use an absolute path.
- **One open instance per directory.** A second `open` on the same directory, in this or
  another process, fails with `CoreApi(LockedDittoWorkingDirectory)` after about a second
  of retries.
- When no directory is set, v5 also looks at the 4.14.x default location and opens an
  existing v4 store there ([versions.md](versions.md#on-disk-store)).

## CAP-04 Authentication and identity

There are two connection modes, chosen with `DittoConfigConnect`:

| Mode | License / auth | Encryption | Use |
|---|---|---|---|
| `SmallPeersOnly { private_key: None }` | offline license token | **none** | development, tests |
| `SmallPeersOnly { private_key: Some(key) }` | offline license token | small-peer traffic encrypted with your key | production without a cloud |
| `Server { url }` | login through the expiration handler | TLS to the server | Ditto cloud or self-hosted server |

## Small-peers-only mode

<!-- snippet: rust-activate-license -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```rust
fn activate(ditto: &Ditto) -> Result<(), DittoError> {
    // Small-peers-only mode only. Equivalent: ditto.set_offline_only_license_token(&token)
    ditto.set_license_from_env("DITTO_OFFLINE_LICENSE")
}
```
<!-- /snippet -->

- `sync().start()` before activation fails `ErrorKind::NotActivated` (executed).
- A bad token fails `ErrorKind::License` ("The license failed verification…"); a
  missing environment variable fails `ErrorKind::Config`.
- In Server mode, `set_offline_only_license_token` returns `ErrorKind::Internal` with a
  message naming v4 identity types ("…only be used for SharedKey or OfflinePlayground
  identities"): the token does not apply to that mode.
- `private_key` is a `Vec<u8>` holding your shared private key. Every peer must use the
  same key. Load it from a secret store; never commit it. The key format and generation
  procedure are in <https://docs.ditto.live/sdk/latest/auth-and-authorization/certificate-based-security>.

## Server mode

Connect to Ditto's cloud ("Big Peer") or a self-hosted server. The database ID must be
the UUID from the portal: a non-UUID string fails `open` with
`ValidationInvalidDittoConfig: … Provided App ID was not a valid UUID` (executed). Ditto
requires an expiration handler; it is called immediately after it is set (with zero time
remaining) and again before each expiry:

<!-- snippet: rust-server-mode -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```rust
/// A handler that needs state is a type implementing the trait: an `async move` closure
/// that captures a value is not `Fn` and is rejected ("async closure does not implement
/// `Fn` because it captures state from its environment").
struct Login {
    token: String,
    /// The authentication webhook name from the Ditto portal. For a development token,
    /// pass `dittolive_ditto::auth::get_development_provider()` (5.0.x: `identity::`).
    provider: String,
}

impl DittoAuthExpirationHandler for Login {
    async fn on_expiration(&self, ditto: &Ditto, _remaining: Duration) {
        let Some(auth) = ditto.auth() else { return };
        // In production, fetch a fresh token from your identity service here (bounded by
        // a timeout) instead of reusing a stored one.
        if let Err(error) = auth.login(&self.token, &self.provider) {
            eprintln!("Ditto login failed: {error}");
        }
    }
}

async fn open_online(url: &str, database_id: &str, login: Login) -> anyhow::Result<Ditto> {
    let connect = DittoConfigConnect::Server { url: url.parse()? };
    let ditto = Ditto::open(DittoConfig::new(database_id, connect)).await?;
    let auth = ditto.auth().expect("auth exists in Server mode");
    auth.set_expiration_handler(login);
    ditto.sync().start()?;
    Ok(ditto)
}
```
<!-- /snippet -->

- Three handler forms: a type implementing `DittoAuthExpirationHandler` (above — the
  only form that can carry state such as a token client), a stateless async closure
  `async |ditto: &Ditto, remaining| { … }`, or `|ditto: &Ditto, remaining| async { … }`.
  Annotate `&Ditto` in closures; inference fails without it. Capturing state in an
  `async move` closure is rejected at compile time (executed).
- It runs on a Ditto thread in a temporary runtime
  ([concurrency.md](concurrency.md#the-auth-expiration-handler)). `login` is synchronous.
- `ditto.auth()` is `None` in small-peers-only mode. `DittoAuthenticator` is `Clone`;
  `is_authenticated()`, `user_id()` and `logout(|ditto| …)` are on it. `logout` stops
  sync, so `sync().start()` again after the next login.
- A failed login is `ErrorKind::Authentication`;
  `DittoError::get_authentication_client_feedback()` carries the provider's payload.
- 5.0.x has this API in the `identity` module; 5.1.0 adds `auth` and deprecates
  `identity`. `DittoAuthenticationEventHandler` is a leftover with no consumer.
- Data authorization (which documents a user may sync) is server configuration:
  <https://docs.ditto.live/sdk/latest/auth-and-authorization/data-authorization>.

## CAP-05 Lifecycle: start/stop sync, shutdown, ownership

| Call | Notes |
|---|---|
| `ditto.sync().start()` | `Result`; `NotActivated` without a license |
| `ditto.sync().stop()` | stops all transports; subscriptions stay registered |
| `ditto.sync().is_active()` | `bool` |
| `drop(ditto)` / `ditto.close()` | stops sync and shuts the instance down; `close(self)` is a plain drop |

Ownership rules ([lifetimes.md](lifetimes.md#the-ditto-instance)): one instance per
persistence directory, shared as `Arc<Ditto>`, alive for the whole program, torn down
after its observers and subscriptions are cancelled. The full pattern is
[tokio.md](tokio.md#graceful-shutdown). When to start and stop sync in an app lifecycle
is covered at <https://docs.ditto.live/sdk/latest/sync/syncing-data>.
