## CAP-16 Error handling

Every fallible SDK call returns `Result<_, dittolive_ditto::error::DittoError>`
(`DittoError` is in the prelude). `DittoError` is `Send + Sync + 'static` and implements
`std::error::Error`, so `?` into `anyhow::Error` or a `thiserror` enum works. It has no
`source()`: the cause is in its `Display` text.

| Method | Returns |
|---|---|
| `error.kind()` | `ErrorKind` (`Copy`, `PartialEq`, `#[non_exhaustive]`) |
| `error.to_string()` | `"<CoreApiErrorKind>: <description>"` for core errors |
| `error.get_authentication_client_feedback()` | provider payload after a failed login |
| `error.is_encryption_error()` / `encryption_error_kind()` | 5.2.0; not reachable from Rust, which has no encryption at rest |

`ErrorKind` variants: `Authentication`, `Config`, `FfiLegacy`, `Internal`,
`InvalidInput`, `IO`, `License`, `NotActivated`, `NonExtant`, `ReleasedDittoInstance`,
`Deprecation`, and `CoreApi(CoreApiErrorKind)`. Most query and store failures are
`CoreApi(..)`.

## Matching

`CoreApiErrorKind` is a newtype over an FFI code with associated constants, not an enum:
match the constants inside `ErrorKind::CoreApi(..)` and always keep a `_` arm, because
new codes appear in minor releases. The block is generated from a test that CI runs on
every supported 5.x line:

<!-- snippet: rust-error-match -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```rust
use dittolive_ditto::error::{CoreApiErrorKind, ErrorKind};

async fn insert_once(store: &Store, id: &str) -> Result<bool, DittoError> {
    match store
        .execute((
            "INSERT INTO cars DOCUMENTS (:car)",
            json!({ "car": { "_id": id } }),
        ))
        .await
    {
        Ok(_) => Ok(true),
        // A duplicate `_id` under the default FAIL policy. Its kind differs by version
        // (5.0.x: StoreDatabase; 5.1.0+: DqlEvaluationError); the message does not.
        Err(error) if error.to_string().contains("Identifier conflict") => Ok(false),
        Err(error) => match error.kind() {
            ErrorKind::CoreApi(CoreApiErrorKind::DqlQueryCompilation) => {
                panic!("bug in a hard-coded query: {error}") // aborts: Ditto is open
            }
            _ => Err(error),
        },
    }
}
```
<!-- /snippet -->

The `panic!` arm is deliberate: with Ditto open, it aborts the process, which is the
right outcome for a bug in a constant query and the wrong one for anything input-driven.

## The failures you will actually hit

All executed on 5.0.4, 5.1.0 and 5.2.0 (the 4.14.x row on 4.14.7):

| Situation | `kind()` | Display (abridged) |
|---|---|---|
| Plain `INSERT` of an existing `_id` | `CoreApi(DqlEvaluationError)` (5.0.x: `CoreApi(StoreDatabase)`) | `… Identifier conflict on document "dup": using FAIL conflict policy` |
| DQL syntax error | `CoreApi(DqlQueryCompilation)` | `… DQL parser error: Unexpected token …` |
| Non-`SELECT` observer | `CoreApi(DqlUnsupported)` | `… non-SELECT statement in store observer` |
| `sync().start()` before a license | `NotActivated` | `Sync could not be started because Ditto has not yet been activated…` |
| Invalid license token | `License` | `The license failed verification…` |
| Second instance on one directory | `CoreApi(LockedDittoWorkingDirectory)` (5.1.0: `open` hangs instead) | `File already locked … Multiple Ditto instances cannot run at the same time within the same working directory…` |
| Server mode, non-UUID database ID | `CoreApi(ValidationInvalidDittoConfig)` | `Invalid DittoConfig: Provided App ID was not a valid UUID` |
| Write in a read-only transaction | `CoreApi(StoreTransactionReadOnly)` | `A mutating DQL query was attempted using a read-only transaction.` |
| `system_parameters` containing JSON `null` | `InvalidInput` (5.2.0; 5.1.0: `open` hangs) | `system parameter … contains JSON null…` |
| 4.14.x mutating DQL before `disable_sync_with_v3()` | `CoreApi(DqlUnsupported)` | `… Mutating DQL statements require that your application is updated to the latest version. Please configure your app to disable sync with V3 to use DQL` |

Display texts include a URL to the DQL guide; do not match on whole strings. Match on
`kind()`, and where one kind covers several causes or the kind changed between versions
(the duplicate-`_id` row), on a stable fragment such as `"Identifier conflict"`.

## Failures that are not `DittoError`

| Symptom | Cause |
|---|---|
| `Process aborting due to panic`, SIGABRT | any panic after `Ditto::open` ([concurrency.md](concurrency.md#panics-abort-the-process)) |
| SIGABRT some time after a `timeout` fired | a cancelled `Ditto::open` |
| a task that never completes | `store().execute` inside a transaction, a transaction after a cancelled one, or an un-acked `signal_next` |
| build error `E0690` in `dittolive-ditto-sys` | rustc 1.98+ ([setup.md](setup.md#the-toolchain-pin)) |
| build panic `Failed to download Ditto SDK binary component` | no network, no `curl`, or an unsupported target |

## Retry, surface, or fail

- **Fail fast at start-up** on `open`, license and configuration errors: they do not fix
  themselves.
- **Surface** `CoreApi(DqlEvaluationError)` conflicts and validation errors to the caller
  as domain errors (`AlreadyExists`, `Invalid`).
- **Retry** only I/O-flavoured kinds (`IO`, `CoreApi(IoOperationFailed)`) and
  authentication through the expiration handler, which Ditto re-invokes.
- **Never retry `LockedDittoWorkingDirectory` in a loop**: another instance owns the
  directory. Find it.
