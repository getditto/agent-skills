## CAP-07 Sync subscriptions and sync scopes

```text
Sync::register_subscription<Q>(&self, query: Q) -> Result<Arc<SyncSubscription>, DittoError>
Sync::subscriptions(&self) -> HashSet<SyncSubscription>   // a snapshot
SyncSubscription::{cancel(), is_cancelled(), query_string(), query_arguments_json_str()}
```

```rust
fn subscribe_to_customer(
    ditto: &Ditto,
    customer: &str,
) -> Result<std::sync::Arc<dittolive_ditto::sync::SyncSubscription>, DittoError> {
    // Keep the Arc and call cancel() when the data is no longer needed:
    // dropping it does not stop the subscription.
    ditto.sync().register_subscription((
        "SELECT * FROM orders WHERE customer = :customer",
        json!({ "customer": customer }),
    ))
}
```
<!-- /snippet -->

- A subscription asks peers for matching documents; it delivers nothing to your code.
  Read the synced data with an observer or `execute`.
- **Dropping the `Arc` does not cancel it** (documented and executed). Cancel it, or hold
  a `Cancelling` guard ([tokio.md](tokio.md#cancel-on-drop-guard)).
- It stays registered across `sync().stop()`/`start()` and applies whenever sync is
  active.
- Subscription queries have restrictions (for example on `LIMIT` and `ORDER BY`):
  <https://docs.ditto.live/sdk/latest/sync/syncing-data>.
- **Sync scopes** (`ALTER SYSTEM SET USER_COLLECTION_SYNC_SCOPES = …`) are DQL through
  `execute`; see <https://docs.ditto.live/sdk/latest/sync/sync-scopes>.
  `ditto.small_peer_info().set_sync_scope(DittoSmallPeerInfoSyncScope::LocalPeerOnly)`
  controls only the `__small_peer_info` collection
  ([observability.md](observability.md#small-peer-info)).

## CAP-14 Sync status and local commit tracking

There is no dedicated sync-status API in Rust; status is data, read with DQL:

1. **`QueryResult::commit_id() -> Option<NonZeroU64>`** is the local commit a write
   produced ([store.md](store.md#writes)).
2. **The `system:data_sync_info` virtual collection** has one row per peer connection,
   including `documents.sync_session_status` and
   `documents.synced_up_to_local_commit_id`. It is readable with `execute` and
   observable (executed on 5.0.4–5.2.0: both work, and it is empty without peers):

<!-- snippet: rust-sync-info -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```rust
fn watch_sync_info(
    ditto: &Ditto,
) -> Result<std::sync::Arc<dittolive_ditto::store::StoreObserver>, DittoError> {
    ditto
        .store()
        .register_observer("SELECT * FROM system:data_sync_info", |result| {
            for item in result.iter() {
                println!("sync info: {}", item.json_string());
            }
        })
}
```
<!-- /snippet -->

A write has reached a peer once that peer's `documents.synced_up_to_local_commit_id` is
at least the write's `commit_id()`. Observe
`SELECT _id, documents.sync_session_status, documents.synced_up_to_local_commit_id FROM
system:data_sync_info` and compare. Field semantics come from
<https://docs.ditto.live/sdk/latest/sync/monitoring-sync-status>; they were not exercised
here because they need a second peer. For connectivity alone, the presence graph has
`Peer::is_connected_to_ditto_server` ([presence.md](presence.md)).
