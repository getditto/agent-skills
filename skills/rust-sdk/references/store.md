## CAP-08 Querying the store: executing DQL

```text
Store::execute<Q>(&self, query: Q) -> impl Future<Output = Result<QueryResult, DittoError>>
  where Q: IntoQuery, Q::Args: Serialize
```

`IntoQuery` is implemented for `String`, `&str` (via `&Q`), `(query, args)` tuples and
`dql::Query<A>`. `ditto.store()` returns `&Store`; `Store` is `Clone + Send + Sync` if a
task needs to own one. `execute` completes inside its first poll: see
[tokio.md](tokio.md#heavy-queries-off-the-async-workers) before running a large query on
an async worker.

```rust
#[derive(Debug, Serialize, Deserialize)]
struct Order {
    #[serde(rename = "_id")]
    id: String,
    customer: String,
    total_cents: u64,
}

#[derive(Serialize)]
struct ByCustomer<'a> {
    customer: &'a str,
}

async fn orders_for(store: &Store, customer: &str) -> Result<Vec<Order>, DittoError> {
    let result = store
        .execute((
            "SELECT * FROM orders WHERE customer = :customer ORDER BY total_cents DESC",
            ByCustomer { customer },
        ))
        .await?;
    result
        .iter()
        .map(|item| item.deserialize_value::<Order>())
        .collect()
}
```

## Arguments

- Pass `(query, args)` where `args` serializes to a **map**: `json!({ … })`, a
  `#[derive(Serialize)]` struct (above), or a `HashMap`. Placeholders are `:name`.
- Arguments are CBOR-encoded with `serde_cbor::to_vec(..).unwrap()`: a `Serialize` impl
  that returns an error **panics**, and with Ditto open that aborts. Keep argument types
  plain.
- Placeholders cannot name a collection (`FROM :c` is invalid). Build the string, and
  never interpolate untrusted values into it.
- Never `format!` user input into DQL; bind it as an argument.

## Reading results

| Call | Returns | Notes |
|---|---|---|
| `result.item_count()` | `usize` | `0` for mutations |
| `result.iter()` / `&result` in `for` | `QueryResultItem`s | |
| `result.get_item(i)` | `Option<QueryResultItem>` | |
| `item.deserialize_value::<T>()` | `Result<T, DittoError>` | `T: DeserializeOwned`, via CBOR |
| `item.value()` | `Arc<HashMap<Box<str>, CborValue>>` | use `CborValueGetters` (`as_str`, `as_f64`, `as_object`, `get`) from the prelude |
| `item.json_string()` | `String` | handy for logs |
| `item.cbor_data()` | `Vec<u8>` | raw CBOR |

Typing rules (executed):

- Integers you write come back as integers: `{"count": 3}` deserializes into `u64`/`i64`.
- **PN counters come back as floating-point numbers**: read them as `f64`.
- `_id` maps to a field with `#[serde(rename = "_id")]`. Missing fields fail
  deserialization: mark optional ones `Option<T>` with `#[serde(default)]`, because
  documents synced from other peers may predate a field.
- `QueryResult` does not implement `Debug`: `unwrap_err()` on a `Result<QueryResult, _>`
  does not compile; use `.err().expect(..)` or `match`.

## Writes

<!-- snippet: rust-write-result -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```rust
async fn upsert(store: &Store, order: &Order) -> Result<(), DittoError> {
    let result = store
        .execute((
            "INSERT INTO orders DOCUMENTS (:order) ON ID CONFLICT DO UPDATE",
            json!({ "order": order }),
        ))
        .await?;
    // Mutations return no rows; the affected IDs and the local commit are on the result.
    for id in result.mutated_document_ids() {
        println!(
            "wrote {}",
            id.to_query_compatible(StringPrimitiveFormat::WithoutQuotes)
        );
    }
    println!("commit: {:?}", result.commit_id());
    Ok(())
}
```
<!-- /snippet -->

- Plain `INSERT` of an existing `_id` fails: "Identifier conflict on document … using FAIL
  conflict policy" (`CoreApi(DqlEvaluationError)`; 5.0.x `CoreApi(StoreDatabase)`, executed). Add `ON ID CONFLICT DO
  UPDATE` for upserts. Which conflict policy and which update form merge correctly
  across peers is `data-modeling`'s topic (<https://docs.ditto.live/key-concepts/document-model>).
- `result.commit_id()` is `Some` for a committed local write and `None` inside an
  uncommitted transaction. `mutated_document_ids()` lists the affected `DocumentId`s;
  render one with `to_query_compatible(StringPrimitiveFormat::WithoutQuotes)`.
- Batch many documents into one statement (`DOCUMENTS (:a), (:b), …`) or a transaction
  rather than thousands of `execute` calls; each call is one synchronous FFI round trip.

<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```rust
/// Reserves `quantity` units if enough stock remains. `stock` is a PN counter: DQL
/// returns counter values as floating-point numbers.
async fn reserve(store: &Store, sku: &str, quantity: f64) -> Result<bool, DittoError> {
    let outcome = store
        .transaction(async |txn| {
            let args = json!({ "sku": sku, "quantity": quantity, "delta": -quantity });
            let stock = txn
                .execute(("SELECT stock FROM products WHERE _id = :sku", args.clone()))
                .await?
                .get_item(0)
                .and_then(|item| item.value().get("stock")?.as_f64())
                .unwrap_or(0.0);
            if stock < quantity {
                return Ok(TransactionCompletionAction::Rollback);
            }
            // Only `txn.execute` here: `store.execute` inside the closure deadlocks.
            txn.execute((
                "UPDATE products APPLY stock PN_INCREMENT BY :delta WHERE _id = :sku",
                args.clone(),
            ))
            .await?;
            txn.execute((
                "INSERT INTO reservations DOCUMENTS ({ 'sku': :sku, 'quantity': :quantity })",
                args,
            ))
            .await?;
            Ok::<_, DittoError>(TransactionCompletionAction::Commit)
        })
        .await?;
    Ok(matches!(outcome, TransactionCompletionAction::Commit))
}
```
<!-- /snippet -->

Executed on 5.0.4–5.2.0:

- Returning `Ok(TransactionCompletionAction::Rollback)` or any `Err` discards the writes;
  `Ok(Commit)` or any other `Ok` value commits.
- `Ok(&TransactionCompletionAction::Rollback)` (a reference) **commits**: the SDK
  recognizes only an owned `TransactionCompletionAction` through its `Any` downcast
  (`src/store/transactions/impls.rs`).
- An `Err` from `txn.execute` does not roll back by itself; returning it with `?` does.
  If the rollback then fails, its error replaces yours.
- Type inference usually needs `Ok::<_, DittoError>(..)` or `transaction::<_, MyError>`.
- `TransactionCompletionAction` is `#[must_use]`.
- Hazards: `ditto.store().execute` inside the closure deadlocks; cancelling the
  `transaction` future wedges later transactions
  ([concurrency.md](concurrency.md#cancellation-safety)). Read-only work:
  `let mut options = CreateTransactionOptions::new(); options.is_read_only = true;`;
  a write in it fails `CoreApi(StoreTransactionReadOnly)`. `options.hint` names the
  transaction in logs.
- Transaction semantics, isolation and limits across peers:
  <https://docs.ditto.live/sdk/latest/crud/transactions>.

## CAP-10 Indexing

No index API: indexes are DQL through `execute` (executed):

<!-- snippet: rust-index-evict -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```rust
async fn maintain(store: &Store) -> Result<(), DittoError> {
    store
        .execute("CREATE INDEX IF NOT EXISTS orders_by_customer ON orders (customer)")
        .await?;
    let evicted = store
        .execute((
            "EVICT FROM orders WHERE created_at < :cutoff",
            json!({ "cutoff": "2026-01-01T00:00:00Z" }),
        ))
        .await?;
    println!(
        "evicted {} local document(s)",
        evicted.mutated_document_ids().len()
    );
    Ok(())
}
```
<!-- /snippet -->

`CREATE INDEX` is local to the device, not synced. Composite (multi-column) indexes and
`ADVISE` need 5.1.0+ ([versions.md](versions.md)); grammar is `write-dql`'s, otherwise
<https://docs.ditto.live/dql/indexing>.

## CAP-17 Device storage management and eviction

`EVICT` (above) removes documents from this device only; they are not deleted for other
peers, and an active subscription that matches them syncs them back. Cancel or narrow the
subscription first. Measure with `ditto.disk_usage()` ([observability.md](observability.md#disk-usage)).
`ditto.run_garbage_collection()` reclaims space after a large eviction. Strategy:
<https://docs.ditto.live/sdk/latest/sync/device-storage-management>.
