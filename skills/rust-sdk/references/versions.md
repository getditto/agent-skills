## CAP-19 v4 to v5 migration, API and on-disk store

The v4 → v5 migration guide: <https://docs.ditto.live/sdk/latest/migration-guides/rust-v4>.
4.14.x already contains the v5 constructor, so a 4.14.x app can move to `DittoConfig`
first and change the DQL method names at the upgrade.

## Construction

4.14.x has two forms. The builder is deprecated ("will be removed in SDK 5.0") and gone in
5.0 (generated from code compiled against 4.14.7):

<!-- snippet: rust-v4-builder -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```rust
#![allow(deprecated)]

use std::sync::Arc;

use dittolive_ditto::{identity, prelude::*};

/// 4.14.x only. Deprecated there ("will be removed in SDK 5.0"); use DittoConfig instead.
pub fn open_with_v4_builder() -> Result<Ditto, DittoError> {
    Ditto::builder()
        .with_root(Arc::new(PersistentRoot::from_current_exe()?))
        .with_identity(|root| identity::OfflinePlayground::new(root, AppId::from_env("APP_ID")?))?
        .build()
}
```
<!-- /snippet -->

The `DittoConfig` form runs unchanged on 4.14.7 and every 5.x line (executed): the
4.14.7 fixture and [the minimal app](../examples/minimal-app.md) open Ditto identically.

| v4 identity | v5 `DittoConfigConnect` |
|---|---|
| `OfflinePlayground` | `SmallPeersOnly { private_key: None }` + offline license |
| `SharedKey` | `SmallPeersOnly { private_key: Some(key) }` + offline license |
| `OnlinePlayground` | `Server { url }` + development provider login in the expiration handler |
| `OnlineWithAuthentication` | `Server { url }` + your provider in the expiration handler |
| `Manual` | no equivalent |

## Query, observer and subscription methods

The names flip between lines: the 4.14.x "current" methods carry `_v2`, and the
unsuffixed 4.14.x methods are deprecated and take a separate arguments parameter.

| Purpose | 4.14.x | 5.x |
|---|---|---|
| Execute DQL | `store().execute_v2((q, args))` | `store().execute((q, args))` |
| Observe | `store().register_observer_v2(q, cb)` | `store().register_observer(q, cb)` |
| Observe with back-pressure | `register_observer_with_signal_next_v2` | `register_observer_with_signal_next` |
| Subscribe | `sync().register_subscription_v2(q)` | `sync().register_subscription(q)` |
| List subscriptions | `sync().subscriptions_v2()` | `sync().subscriptions()` |
| Start sync | `sync().start()` (`ditto.start_sync()` deprecated) | `sync().start()` |

**Mutating DQL on 4.14.x requires `ditto.disable_sync_with_v3()` first.** Without it
(executed on 4.14.7):
`DqlUnsupported: <dql> Unsupported feature: Encountered `INSERT` statement. Mutating DQL
statements require that your application is updated to the latest version. Please
configure your app to disable sync with V3 to use DQL`. The opt-out is persisted in the
store: once set, later opens accept mutations without calling it again (executed). It
is one-way and stops sync with v3 peers. 5.0.x and 5.1.x keep a working
`disable_sync_with_v3`; in 5.2.0 it is a hidden no-op.

**`DQL_STRICT_MODE` default changed:** v4 defaulted to `true` (nested objects are
registers), v5 to `false` (objects are maps). A migrating app that relied on v4 merge
behaviour sets it explicitly before `open` (documented in the rust-v4 guide; not
executed here):
`config.system_parameters.insert("DQL_STRICT_MODE".into(), serde_json::json!(true));`.
What the two modes mean is `data-modeling`'s topic.

## Removed v4 APIs

An agent trained on older code will emit these; none exist in 5.x:

- **Construction:** `Ditto::builder()`, `DittoBuilder` (`with_root`, `with_identity`,
  `with_transport_config`, `with_minimum_log_level`, `with_temp_dir`, `build`),
  `Ditto::new(app_id)`.
- **Identity:** `identity::{Identity, OnlinePlayground, OnlinePlaygroundV2,
  OfflinePlayground, OnlineWithAuthentication, SharedKey, Manual}`, `ValidityListener`.
- **Renames:** `AppId` → `DatabaseId`; `SiteId` removed; `ditto.authenticator()` →
  `ditto.auth()`; `current_transport_config()` → `transport_config()`;
  `persistence_directory()`/`root_dir()`/`data_dir()` → `absolute_persistence_directory()`.
- **Logging statics on `Ditto`** (`Ditto::set_minimum_log_level` …) → `DittoLogger::*`.
- **Legacy query builder:** `store().collection(..)`, `collections()`,
  `with_batched_write`, `timeseries()`, and the types `Collection`,
  `PendingCursorOperation`, `PendingIdSpecificOperation`, `LiveQuery`, `LiveQueryEvent`,
  `Subscription`, `DittoDocument`, `DittoMutDocument`, `DittoCounter`, `DittoRegister`.
  Use DQL.
- **DQL leftovers:** `dql::{QueryArguments, QueryV2}`; `IntoQuery` now lives in
  `dql::query` and the prelude.
- **Presence:** `Presence::observe`, `Presence::exec`, `Ditto::observe_peers` →
  `presence().register_observer(..)`.
- **Cargo features:** `experimental`, `experimental-bus`.

## On-disk store

| Default directory (no `persistence_directory`) | |
|---|---|
| 4.14.x builder (`PersistentRoot::from_current_exe()`) | the executable's directory itself |
| 4.14.x `DittoConfig` and all 5.x | `<executable's directory>/ditto-<database id, lowercased>` |

When no directory is set, 5.x also looks at the v4 builder location and, if a database is
there and none is at the v5 default, opens the v4 one with the warning "Conflicting
pre-existing default persistence directories found… defaulting to legacy v4" (source:
`crates/ditto-core/src/lib.rs` at `sdk-release-5.2.0`).

Executed with an explicit directory: a store written by 4.14.7 opens in 5.2.0, which
migrates it in place (logging harmless `Failed to drop V2 DQL index storage …
TableNotFound` warnings), reads the documents and writes new ones. 4.14.7 then reopened
the migrated store in this simple case; that is not a supported downgrade path. Back up
the directory before upgrading. **Set an explicit, absolute `persistence_directory` and
keep it identical across versions.**

## Changes within 5.x

**5.1.0** (vs 5.0.4):

- New `auth` module (`DittoAuthenticator`, `auth::get_development_provider()`); the
  `identity` module is deprecated ("Use the `auth` module instead"). 5.0.x code must use
  `identity::`.
- `store::SortDirection` deprecated (use DQL `ORDER BY`).
- `TransportConfig.peer_to_peer.multicast_beta` and `ConnectionType::Multicast` (private
  beta). Exhaustive `PeerToPeer { .. }` literals from 5.0.x stop compiling.
- DQL gains JOINs, composite indexes, `RETURNING` and `ADVISE` (`write-dql` owns them).

**5.2.0** (vs 5.1.0):

- Support bundles and their system parameters: `EXECUTE FUNCTION
  system_request_support_bundle()`, `system:support_bundles`
  ([observability.md](observability.md#support-bundles-520)). Executed: the function fails
  on 5.0.4 and 5.1.0.
- `system_parameters` validated before `open`: JSON `null` → `ErrorKind::InvalidInput`.
- `disable_sync_with_v3()` becomes a hidden no-op.
- `DatabaseId::default_auth_url()` / `default_sync_url()` deprecated.
- `DittoError::is_encryption_error()` / `encryption_error_kind()` and new
  `CoreApiErrorKind` constants (`StoreNoTransaction`,
  `AuthenticationLoginCredentialsRejected`, `AuthenticationLoginRetryableOrUnknown`,
  `EncryptionKey*`). There is still no public encryption-at-rest API.
- The prelude no longer exports `BoxedDocument`.

## Behaviour differences within 5.x

All executed:

| Behaviour | 5.0.4 | 5.1.0 | 5.2.0 |
|---|---|---|---|
| Second `open` on a directory already open | `LockedDittoWorkingDirectory` | **hangs** | `LockedDittoWorkingDirectory` |
| JSON `null` in `system_parameters` | not tested | **`open` hangs** | `InvalidInput` |
| Thread running the auth expiration handler | a worker of the app's runtime | Ditto thread (`tokio-rt-worker`) | Ditto thread |
| Support bundles | absent | absent | present |
| Kind of a duplicate-`_id` `INSERT` error | `CoreApi(StoreDatabase)` | `CoreApi(DqlEvaluationError)` | `CoreApi(DqlEvaluationError)` |

Observer, subscription, `signal_next`, panic, cancellation and transaction behaviour is
identical across the three lines.

## Migration checklist

1. Pin `rust-toolchain.toml` (1.91.0) and add the Linux link flag
   ([setup.md](setup.md#linux-the-link-fix)) before touching code.
2. On 4.14.x, switch construction to `DittoConfig` + `Ditto::open`, keeping the same
   explicit persistence directory, and call `disable_sync_with_v3()` once all peers run
   DQL-capable versions.
3. Bump `dittolive-ditto` to 5.x; rename `execute_v2` → `execute`,
   `register_observer_v2` → `register_observer`, `register_subscription_v2` →
   `register_subscription`.
4. Replace every legacy query-builder call with DQL (`write-dql` skill, or
   <https://docs.ditto.live/sdk/latest/migration-guides/rust-dql>).
5. On 5.1.0+, change `identity::` imports to `auth::`.
6. Add `cancel()` (or guards) for every observer and subscription: drop never cancelled.
7. Run the app against a copy of a production store before shipping.
