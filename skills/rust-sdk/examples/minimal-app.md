A complete, runnable program: every file needed to build it is below. The fixture
script builds, lints (`cargo clippy --all-targets -- -D warnings`) and runs it against
5.0.4, 5.1.0 and 5.2.0; CI runs that script. Longer form of `SKILL.md` § *Minimum viable app*.

## What it does

Opens Ditto in small-peers-only mode (no cloud), activates an offline license, starts
sync, registers a subscription and an observer, writes a document, waits for the
observer to see it, reads it back as a typed struct, then cancels the handles and shuts
down. The observer hands its count to `main` through a `tokio::sync::watch` channel
because it runs on a Ditto thread, not a Tokio task.

## .cargo/config.toml (Linux)

Required on Linux, harmless elsewhere: without it the program does not link
([setup.md](../references/setup.md#linux-the-link-fix)).

<!-- snippet: rust-linux-link-fix -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```toml
# libdittoffi.a carries its own copy of Rust's std. On Linux, GNU ld ("multiple definition
# of `std::io::error::Error::new'") and rust-lld ("duplicate symbol: __rustc::rust_panic")
# both reject the duplicates; macOS's linker accepts them. Ditto's own CI links this way.
[target.'cfg(target_os = "linux")']
rustflags = ["-C", "link-arg=-Wl,--allow-multiple-definition"]
```

## Program

`src/main.rs`:

<!-- snippet: rust-minimal-app -->
<!-- Generated by scripts/sync-snippets.py from code CI runs. Edit the marked source, not this block. -->
```rust
use std::time::Duration;

use anyhow::Context as _;
use dittolive_ditto::prelude::*;
use serde::{Deserialize, Serialize};
use serde_json::json;
use tokio::sync::watch;

#[derive(Debug, Serialize, Deserialize)]
struct Car {
    #[serde(rename = "_id")]
    id: String,
    make: String,
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    // SmallPeersOnly without a key is unencrypted: development and tests only.
    let config = DittoConfig::new(
        "REPLACE_ME_WITH_YOUR_DATABASE_ID",
        DittoConfigConnect::SmallPeersOnly { private_key: None },
    )
    .with_persistence_directory(std::env::temp_dir().join("ditto-minimal-app"));

    let ditto = Ditto::open(config).await?;
    ditto.set_license_from_env("DITTO_OFFLINE_LICENSE")?;
    ditto.sync().start()?;

    // Both handles run until `cancel()` or Ditto shutdown; dropping the Arc does not stop them.
    let subscription = ditto.sync().register_subscription("SELECT * FROM cars")?;

    // The handler runs on a Ditto thread, not a Tokio task: keep it short and
    // non-blocking, and hand the data to async code through a channel.
    let (count_tx, mut count_rx) = watch::channel(0_usize);
    let observer = ditto
        .store()
        .register_observer("SELECT * FROM cars", move |result| {
            count_tx.send_replace(result.item_count());
        })?;

    let car = Car {
        id: "car1".into(),
        make: "Toyota".into(),
    };
    ditto
        .store()
        .execute((
            "INSERT INTO cars DOCUMENTS (:car) ON ID CONFLICT DO UPDATE",
            json!({ "car": car }),
        ))
        .await?;

    tokio::time::timeout(Duration::from_secs(10), count_rx.wait_for(|n| *n >= 1))
        .await
        .context("observer did not report the insert within 10 s")??;
    println!("observer: {} car(s)", *count_rx.borrow());

    let result = ditto
        .store()
        .execute((
            "SELECT * FROM cars WHERE _id = :id",
            json!({ "id": "car1" }),
        ))
        .await?;
    let stored: Car = result
        .get_item(0)
        .context("car1 not found")?
        .deserialize_value()?;
    println!("read-back make: {}", stored.make);
    println!("SDK version: {}", Ditto::version());

    observer.cancel();
    subscription.cancel();
    ditto.sync().stop();
    ditto.close();
    Ok(())
}
```
<!-- /snippet -->

Two lines carry the skill's main traps. `observer.cancel()` and
`subscription.cancel()` are required: dropping the `Arc`s would leave both running. And
the closure only calls `send_replace`, which never blocks and cannot panic. A panic
there aborts the process.

## Running it

```bash
export DITTO_OFFLINE_LICENSE='REPLACE_ME_WITH_YOUR_OFFLINE_LICENSE_TOKEN'
cargo run 2>/dev/null
```

The first build downloads `libdittoffi.a` (5.2.0: 110 MB macOS, 196 MB Linux x86_64) from `software.ditto.live`
through `curl`; offline builds need `DITTOFFI_SEARCH_PATH`
([setup.md](../references/setup.md#the-native-library)). Ditto logs to stderr, so
`2>/dev/null` leaves only the program's output. Quiet it in code with
`DittoLogger::set_minimum_log_level(LogLevel::Warning)`.

## The v4 leg (4.14.7)

4.14.7 already has `DittoConfig` and `Ditto::open`, but its DQL methods carry a `_v2`
suffix and mutating DQL is refused until `disable_sync_with_v3()` is called. The
4.14.7 fixture prints the refusal, then proceeds:

```text
insert before disable_sync_with_v3: DqlUnsupported: <dql> Unsupported feature: Encountered `INSERT` statement. Mutating DQL statements require that your application is updated to the latest version. Please configure your app to disable sync with V3 to use DQL
observer: 1 car(s)
SDK version: 4.14.7
```

The v4 forms are in [versions.md](../references/versions.md#query-observer-and-subscription-methods).
