## Agent Skills v0.6.1

This patch release makes installed skills self-contained. Skills no longer link
to test code, contributor docs or this repository; the tested code they pointed
to is now copied into the skill, and generated from the code CI runs. The bundle
still contains the same thirteen skills as v0.6.0.

### Fixed

- Skills linked to files outside `skills/`, such as `../../tests/js-sdk/README.md`
  and the Kotlin reference projects. Installed skills don't include those files,
  and agents may have no web access, so the links were broken. Each is now local
  content or plain text:
  - `kotlin-sdk`: the minimal test skeleton in `references/testing.md` is now
    generated from the JVM store test CI runs; the hand-written copy had drifted.
    The new `references/reference-projects.md` has the tested JVM and Android
    Gradle files, which `gradle-project-generation.md` tells agents to copy. They
    read the license from the environment or a Gradle property, keep the
    build-time security pins, and leave out CI-only settings. `testing.md` now
    points there instead of carrying its own out-of-date dependency versions, and
    the recommended toolchain text matches them (coroutines 1.11, AGP 9.5.0).
  - `js-web`: the new `references/browser-fixture.md` has the React browser app
    CI runs against WASM.
  - `js-sdk`, `js-node`, `js-react-native`, `js-expo`, `write-dql`, and
    `data-streams`, and the README files of `js-sdk`, `swift-sdk`, `kotlin-sdk`,
    `write-dql`, `data-modeling`, and `ditto-mesh-networking`: links to test
    reports, install guides and the repository README are now plain text.
- The Swift and Kotlin example programs no longer describe themselves as copies
  of a repository file. They are generated from the programs CI compiles and runs;
  their code is unchanged.

### For contributors

- `scripts/sync-snippets.py` copies marked regions of code from `tests/` into
  skill Markdown. CI and the Release workflow run it with `--check`, so generated
  code can't drift from the code CI runs. Hand-written code blocks are not checked.
  It replaces the old "This is a copy of … in the fixture" comparison.
- `scripts/validate-sdk-skills.py` rejects any link out of `skills/` in skill
  Markdown (inline, reference-style or HTML), any reference to this repository
  (github.com, raw.githubusercontent.com, api.github.com or git@ forms) in any
  skill file, and requires SDK example programs to be generated.
- A new CI job assembles the Kotlin JVM and Android reference projects from the
  skill's Markdown alone and builds them, so generated code must build on its own.
- Plugin versions are bumped for plugins whose skills changed: `ditto-dql` 2.0.2,
  `ditto-swift` 1.1.1, and `ditto-js`, `ditto-kotlin`, `ditto-mesh`,
  `ditto-data-modeling`, and `ditto-data-streams` 1.0.1. The Claude Code
  marketplace is 1.4.1.

See CONTRIBUTING.md, "Keep skills self-contained".

### Release assets

- `ditto-skills.tar.gz`: the canonical `skills/` tree, `LICENSE.md`, and
  `skills-manifest.json` at the archive root.
- `skills-manifest.json`: each skill's name, path, and description.

Tests, contributor documentation, and plugin wrappers are excluded from the
archive. The bundle version is independent of individual plugin versions.

### Install with the Ditto CLI

Update existing installations:

```bash
dittosh skills versions
dittosh skills update --all --ref v0.6.1
```

Use `--project <existing-directory>` to update a project-local installation.
To add skills you have not installed yet, use `dittosh skills add --all`.
