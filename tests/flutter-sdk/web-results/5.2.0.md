## How these were run

Drive probes, debug build (DDC), `flutter drive -d chrome --headless`:

```bash
tests/flutter-sdk/scripts/run-fixture.sh minimal_app chrome 5.2 \
  integration_test/web/web_all_test.dart integration_test/web/web_51_test.dart
tests/flutter-sdk/scripts/run-fixture.sh minimal_app chrome 5.1 \
  integration_test/web/web_all_test.dart integration_test/web/web_51_test.dart
tests/flutter-sdk/scripts/run-fixture.sh minimal_app chrome 5.0 \
  integration_test/web/web_all_test.dart
```

Build and hosting probes, release builds of `integration_test/web/probe_app.dart`
(`flutter build web --release --no-web-resources-cdn`, plus `--wasm` or
`--base-href /app/`), served from a local Python `http.server`:

```bash
python3 tests/flutter-sdk/scripts/web-probe.py --line 5.2
python3 tests/flutter-sdk/scripts/web-probe.py --line 5.1
```

`web_51_test.dart` holds the two 5.1+ probes; it does not compile on 5.0.4.

## Drive probes, ditto_live 5.2.0

Build mode: debug (DDC). Outcome: pass, `web_all_test.dart` 13 tests, `web_51_test.dart`
2 tests. The value column is the transcript line the probe records and asserts.

| Probe | Outcome |
|---|---|
| `currentPlatform is web` | pass: `Ditto.currentPlatform` is `web` |
| `defaultTargetPlatform is not web on web` | pass: `defaultTargetPlatform` is `macOS` (the host OS). A LAN gate on it is accepted by `updateTransportConfig`, then `sync.start()` throws `DittoException(<validation> Expected valid TransportConfig. Invalid config: The following P2P transports are enabled in the transport config but are not supported in the current environment: LAN)`. The `kIsWeb`-first gate (`enablePeerToPeer`) leaves every transport off and `sync.start()` succeeds |
| `p2p transports disabled by default` | pass: `bluetoothLE=false lan=false awdl=false wifiAware=false` right after `Ditto.open` |
| `withAllPeerToPeerEnabled is a no-op` | pass: `withAllPeerToPeerEnabled(true)` returns an equal config; `setAllPeerToPeerEnabled(true)` leaves all four off; `sync.start()` succeeds |
| `enabling bluetoothLE then sync.start throws DittoException` | pass: `updateTransportConfig` accepts it; `sync.start()` throws synchronously `DittoException(<validation> Expected valid TransportConfig. Invalid config: The following P2P transports are enabled in the transport config but are not supported in the current environment: BluetoothLE)`; `sync.isActive` stays `false` |
| `newAttachment(path) throws DittoException` | pass: the returned Future fails with `DittoException(Creating attachments from files is not supported on Flutter Web.)`; nothing is thrown at the call |
| `newAttachment(Uint8List) succeeds` | pass: 1,024 bytes, metadata `{name: photo.jpg}` |
| `copyToPath throws` | pass: the returned Future fails with `DittoException(Retrieving a filesystem path for attachments is not supported on the Web.)` (a DittoException, not an UnsupportedError) |
| `Attachment.data works` | pass: the 1,024 bytes come back unchanged |
| `exportLogs throws UnsupportedError` | pass: thrown synchronously at the call, `UnsupportedError: Not supported on the web platform` |
| `defaultRootDirectory is empty` | pass: `""`; `ditto.absolutePersistenceDirectory` is `ditto-00000000-0000-0000-0000-000000000000` (a store name, not a path) |
| `bad offline license on web` | pass: `setOfflineOnlyLicenseToken('not-a-license')` does not throw; the console logs `WARN dittoffi: setOfflineOnlyLicenseToken is a no-op on the web platform.` |
| `close then reopen in the same page loses data` | pass: it does **not** lose data. 1 document before `close()`, 1 after a new `Ditto.open` in the same page |
| `DittoSyncPermissions requiredPermissions is empty` | pass: `[]` |
| `registerObserverWithSignalNext works on web` | pass: item counts `[0]`, nothing more for 2 s after three inserts, then `[0, 3]` after `signalNext()` |

## Build and hosting probes, ditto_live 5.2.0

Build mode: release, `--no-web-resources-cdn` (CanvasKit and every other Flutter
resource served from the same origin, so a CSP of `'self'` covers them).

| Probe | Build | Outcome |
|---|---|---|
| `web_default_build` | dart2js | pass: `Ditto.init()`, open, INSERT, SELECT read-back `Toyota`, SDK version `5.2.0` |
| `web_wasm_build` | `--wasm` (runs as dart2wasm, skwasm single-threaded) | **SDK defect**: init and open succeed, but every query result after the first is the first one again: a second INSERT reports the first INSERT's mutated IDs `[blue-toyota]`, and `SELECT * FROM cars` returns 0 items. In the same bundle `1.toJS.hashCode == 2.toJS.hashCode`. The probe asserts this observed behavior |
| `web_no_coop_coep` | dart2js, `--wasm` | pass: without COOP/COEP both bundles initialize and open Ditto (`crossOriginIsolated` false; Flutter warns that skwasm runs single-threaded). With `Cross-Origin-Opener-Policy: same-origin` and `Cross-Origin-Embedder-Policy: require-corp` the wasm bundle is cross-origin isolated and behaves the same (including the defect above). Ditto needs neither header |
| `web_csp` | dart2js, `--wasm` | pass: with `script-src 'self' 'wasm-unsafe-eval'` both bundles start and Ditto initializes (dart2js reads back correctly; dart2wasm shows the defect above). Without `'wasm-unsafe-eval'` neither app reaches `main()`: Flutter's own bootstrap fails first, `Uncaught CompileError: WebAssembly.compileStreaming(): ... Content Security Policy directive: "script-src 'self'"`, so Ditto is never reached |
| `web_base_href` | dart2js, `--base-href /app/` | pass: served only below `/app/`, `Ditto.init()` with defaults fails, `Exception: Failed to initialize Ditto WebAssembly: TypeError: Failed to fetch dynamically imported module: http://127.0.0.1:<port>/assets/packages/ditto_live/lib/assets/ditto.wasm.js` (the shim's default URL is absolute). `Ditto.init(wasmShimUrl: './assets/packages/ditto_live/lib/assets/ditto.wasm.js')` works; the bare `assets/...` form fails with `TypeError: Failed to resolve module specifier`. `wasmUrl` is not needed: the `.wasm` loads through the asset bundle, which follows the base href |
| `web_reload_persistence` | dart2js | pass: 1 document before a page load, 0 after it |
| `web_large_result_jank` | dart2js | recorded (see below) |

`web_large_result_jank`, dart2js release: 5,000 documents (`_id`, two short fields and a
200-character string) inserted in batches of 100, then each query timed in Dart around
`execute` (and, for "+ values", around reading every `item.value`), with the longest
long task (PerformanceObserver `longtask`) and the longest gap between animation frames
the page saw in that window:

| Query | execute (+ decode) | Longest task | Longest frame gap |
|---|---|---|---|
| `SELECT * FROM jank`, items counted only | 20 ms | none over 50 ms | 17 ms |
| `SELECT * FROM jank`, every `item.value` read | 79 ms | 79 ms | 67 ms |
| `SELECT * FROM jank LIMIT 50`, every `item.value` read | 2 ms | none over 50 ms | 17 ms |

From the final `web-probe.py --line 5.2` run; an earlier run of the same build gave
28 ms, 66 ms (one 66 ms task, 50 ms frame gap) and 3 ms. One machine, so read the
numbers as an order of magnitude.

Not measured on dart2wasm: its SELECT returns 0 items (defect above).

## ditto_live 5.1.0

Same toolchain. Drive probes (debug): pass, `web_all_test.dart` 13 and `web_51_test.dart`
2, with the same transcript as 5.2.0 except:

- `enabling bluetoothLE then sync.start throws DittoException` and the LAN gate in
  `defaultTargetPlatform is not web on web`: **`updateTransportConfig` itself throws**
  the same `DittoException(<validation> ... : BluetoothLE)` (or `LAN`) synchronously, so
  `sync.start()` is never reached. The probe asserts this per line.
- `DittoSyncPermissions requiredPermissions is empty`: `[]`.
- `registerObserverWithSignalNext works on web`: `[0, 3]`, as on 5.2.0.

Build and hosting probes (release), `web-probe.py --line 5.1`: 7 of 7 pass with the
same outcomes as 5.2.0, including the dart2wasm defect and the base-href fix.
`web_large_result_jank` (dart2js): `SELECT *` 13 ms counted only, 55 ms with every
`item.value` read (longest task 55 ms, longest frame gap 33 ms), `LIMIT 50` 2 ms.
